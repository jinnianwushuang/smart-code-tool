## 🛡️ 前端代码质量分析平台技术选型白皮书 (V4.0 React 工业版)

## 一、 项目架构：边缘计算 + 分布式管控

系统采用 **“重量级本地客户端 + 轻量级云端后台”** 的协同模式，确保源码安全与分析性能。

- **本地客户端**：利用 **Rust** 的极致性能进行插件化分析与中间数据二次加工。
- **云端服务端**：利用 **NestJS** 进行多项目数据的统一存储、趋势分析与质量报告分发。

---

## 二、 核心技术栈清单

## 1. 表现层 (UI & Interaction)

| 维度         | 技术选型              | 理由                                                                  |
| :----------- | :-------------------- | :-------------------------------------------------------------------- |
| **基础框架** | **React 18 (Hooks)**  | 强大的生态，并发模式（Concurrent Mode）能流畅处理高频更新的分析状态。 |
| **跨端框架** | **Electron**          | 提供本地文件系统访问权限，承载分析引擎运行。                          |
| **组件库**   | **Ant Design (AntD)** | 工业级 UI 标准，内置丰富的表格、树形结构和统计图表组件。              |
| **状态管理** | **Zustand**           | 极其轻量且高性能，非常适合管理复杂的插件调度流与分析进度。            |
| **流程编排** | **React Flow**        | **核心推荐**：用于可视化地组装分析插件（拖拽节点、连线形成工作流）。  |
| **链路展示** | **AntV G6**           | 专门处理大规模代码依赖拓扑图，支持万级节点的流畅缩放与查看。          |

## 2. 计算层 (The High-Performance Engine)

| 维度         | 技术选型              | 理由                                                              |
| :----------- | :-------------------- | :---------------------------------------------------------------- |
| **中控语言** | **Rust (NAPI-RS)**    | 编译为原生 `.node` 模块。负责多线程调度插件、文件 I/O、内存映射。 |
| **解析引擎** | **Oxc / Tree-sitter** | 极速 AST 解析，为后续插件提供基础元数据。                         |
| **并行库**   | **Rayon / Tokio**     | 压榨 CPU 性能，支持多个分析插件在本地并行执行。                   |
| **插件协议** | **Rust Trait System** | 通过定义标准的 `Plugin` 接口，实现各种分析脚本的模块化插拔。      |

## 3. 数据加工与云端管理 (Data & Cloud)

| 维度           | 技术选型             | 理由                                                                    |
| :------------- | :------------------- | :---------------------------------------------------------------------- |
| **中间数据库** | **DuckDB / SQLite**  | 嵌入式分析型数据库，用于存储插件产生的海量中间指标，支持 SQL 二次计算。 |
| **服务端框架** | **NestJS (Node.js)** | 企业级后端框架，负责权限校验、项目成长曲线记录。                        |
| **时序数据库** | **PostgreSQL**       | 记录项目质量随时间变化的快照数据。                                      |
| **报告生成**   | **Puppeteer**        | 将 React 渲染的可视化看板在服务端截取为 PDF 周报。                      |

## 三、 业务执行全链路 (Workflow)

1. **编排阶段 (React Flow)**：用户在 UI 界面通过拖拽节点，将“AST提取”、“复杂度插件”、“代码重复率插件”组装成一条链路。
2. **调度执行 (Rust Engine)**：React 通过 IPC 发送指令，Rust 中控接收配置，启动多线程 Pipeline 执行。
3. **数据落盘 (DuckDB)**：各插件产出的海量原始特征实时写入本地 DuckDB，不占用 Node.js 内存。
4. **二次加工 (SQL Aggregation)**：中控执行 SQL 聚合命令，对数据进行降维、归类、评分，生成结构化的报告 JSON。
5. **指标上报 (NestJS API)**：客户端将评估后的关键指标（非源码）异步推送到 NestJS 服务端。
6. **价值呈现 (Dashboard)**：服务端持久化数据，前端 React 调用 NestJS 接口，展示团队整体的质量分布与成长曲线图。

## 四、 方案优势

- **安全合规**：源码解析全在本地 Rust 引擎完成，云端只记录统计结果。
- **极致交互**：借助 **React Flow**，用户可以直观地定义“分析逻辑”，让复杂的脚本调度变得像搭积木一样简单。
- **性能统治**：Rust + DuckDB 解决了前端工具处理大项目时的卡顿痛点，二次加工能力支持 TB 级扫描结果的瞬时处理。
- **团队度量**：NestJS 的引入让“个人开发工具”进化为“企业级质量资产管理平台”。

## 五、 开发路线图建议

1. **Phase 1**：环境搭建（React 18 + AntD + Electron + NAPI-RS）。
2. **Phase 2**：Rust 中控开发（跑通多线程文件扫描与基础 AST 提取）。
3. **Phase 3**：插件机制（定义 Rust Trait，尝试组装两个简单的分析脚本）。
4. **Phase 4**：二次加工（集成 DuckDB，练习用 SQL 算子对分析结果进行评估）。
5. **Phase 5**：可视化大盘（React Flow 流程图 + G6 依赖链路 + NestJS 数据上报）。
