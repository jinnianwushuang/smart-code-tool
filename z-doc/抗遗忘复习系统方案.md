# 抗遗忘复习清单系统 — 技术调研与方案设计

---

## 一、技术调研结论

### 1.1 开源间隔重复算法方案对比

| 方案                 | 核心特点                                      | 优势                                                                  | 劣势                                   | 适用性                  |
| -------------------- | --------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------- | ----------------------- |
| **ts-fsrs**          | 基于机器学习的三变量记忆模型，Anki 新一代算法 | 科学精准，比 SM-2 减少 20-30% 复习量；TypeScript 原生；npm 周活跃维护 | 面向闪卡场景设计，需适配"文档复习"场景 | ⭐⭐⭐⭐⭐ 核心算法引擎 |
| **SM-2**             | 经典间隔重复算法，Anki 旧版默认               | 简单成熟，实现成本低                                                  | 固定系数，不区分个体差异               | ⭐⭐⭐ 备选方案         |
| **固定艾宾浩斯间隔** | 5min→30min→12h→1d→2d→4d→7d→15d                | 完全符合原始需求，零依赖                                              | 不个性化，无法根据掌握程度动态调整     | ⭐⭐⭐⭐ 降级/入门方案  |

**结论**：采用 **ts-fsrs 作为核心算法引擎**，保留固定间隔作为「经典模式」可选项。纯计算库，无 UI 依赖，~15KB gzip。

### 1.2 IndexedDB 持久化方案对比

| 方案           | 体积           | 特点                                    | 适用场景               |
| -------------- | -------------- | --------------------------------------- | ---------------------- |
| **idb-keyval** | ~600B (brotli) | 极简 key-value API，Jake Archibald 维护 | 键值存储，无需复杂查询 |
| **idb**        | ~1.2KB         | 原生 IndexedDB API 的 Promise 化封装    | 需要索引和范围查询     |
| **Dexie.js**   | ~15KB          | 类 ORM 语法，链式查询，版本迁移         | 中大型应用             |

**结论**：采用 **idb-keyval**。复习数据本质是 `Map<docId, ReviewRecord>` 的键值结构，体积极小，容量远超 localStorage（数百 MB vs 5MB）。

## 二、整体架构设计

### 2.0 核心设计理念：自动感知，零操作

用户在一个页面停留 ≥ 10 分钟（有效阅读时间），系统自动记录为「已学习」。

```
用户阅读文档（正常浏览）
  ↓ 页面停留 ≥ 10 分钟（自动感知，无需点击）
系统自动记录「已学习」→ 触发调度引擎计算首次复习时间
  ↓
到期提醒 → 用户自评（忘了/有印象/记得/秒记）→ 计算下次复习时间
  ↓
循环直到转入长期记忆
```

**有效时间判定规则**：

- 页面 `visibilityState === 'visible'` 时才计时（切 Tab / 最小化不计）
- **visibilitychange 事件驱动**：页面隐藏时停止 timer + 持久化，恢复时重启
- SPA 路由切换时自动重置计时器
- 同一页面多次进入时间累加
- tick 间隔 10 秒（对 600 秒阈值误差可忽略）

## 三、数据模型设计

### 3.1 IndexedDB 存储结构

四工具共用同一个 IDB 数据库：

```
IndexedDB: "smart-code-tool"
├── Store: "quick-tools"
│   ├── "qt:progress"           → ProgressRecord[]   (进度记录)
│   ├── "qt:doubts"             → DoubtRecord[]      (疑惑记录)
│   ├── "qt:notes"              → NoteRecord[]       (笔记记录)
│   ├── "review:records"        → ReviewRecord[]     (复习记录)
│   ├── "review:docSnapshot"    → DocSnapshot        (文档快照)
│   └── "review:settings"       → UserSettings       (用户配置)
```

旧 localStorage 数据（`quick-tools-progress` 等）在首次访问时自动迁移到 IDB 并清除旧键。

### 3.2 核心数据结构

```typescript
// ── 复习记录（每个文档一条，以 docId 为主键）──
interface ReviewRecord {
  docId: string // 文档稳定 ID（与 sidebar 中的 id 对应）
  url: string // 文档路径（stripBase 规范化后）
  title: string // 文档标题（可从 doc-list 同步更新）
  group: string // 所属分组

  autoLearnedAt: string | null // 自动标记「已学习」的时间
  accumulatedSeconds: number // 累计有效阅读秒数

  // FSRS 调度字段
  state: 'new' | 'learning' | 'review' | 'relearning'
  stability: number
  difficulty: number
  due: string // 下次到期时间 (ISO 8601)
  lastReview: string | null

  // 学习历史（完整时间线）
  reviewCount: number
  lapses: number
  history: LearningLogEntry[] // 上限 50 条

  // 元数据
  createdAt: string
  updatedAt: string
  isArchived: boolean // 文档被删除时标记
  isDismissed: boolean // 标记为「已知」，从盲区移除
}

// ── 学习历史条目 ──
interface LearningLogEntry {
  timestamp: string
  type: 'auto-learn' | 'review'
  accumulatedSeconds?: number // 仅 auto-learn
  rating?: 'again' | 'hard' | 'good' | 'easy' // 仅 review
  interval?: number // 仅 review（天）
  elapsedDays?: number // 仅 review
}

// ── 用户配置 ──
interface UserSettings {
  algorithm: 'fsrs' | 'ebbinghaus'
  requestRetention: number // 目标保持率 (0.0-1.0)，默认 0.9
  maximumInterval: number // 最大间隔（天），默认 365
  dailyReviewLimit: number // 每日复习上限，默认 50
  historyLimitPerDoc: number // 单文档学习历史上限，默认 50
  enableNotification: boolean // 是否开启浏览器通知
}
```

### 3.3 Sidebar 菜单模型：文档 ID 锚定

**核心问题**：文档目录调整、文件重命名会导致 URL 变化，用 URL 作锚点会丢失历史。

**解决方案**：每个带 `link` 的叶子菜单项包含 `id` 字段（24 字符 nanoid）作为稳定锚点。

```javascript
// 升级前
{ text: 'Vue 3 手册', link: '/handbook/frontend/vue3-handbook' }
// 升级后
{ text: 'Vue 3 手册', link: '/handbook/frontend/vue3-handbook', id: 'a3f8c1e9b2d4Xk9mPq2vLwR7' }
```

- `id` 仅加在带 `link` 的叶子节点上
- VitePress 会忽略不认识的字段
- `id` 一旦生成永不修改

### 3.4 doc-list.json 格式

```json
{
  "version": 1,
  "updatedAt": "2026-10-05T10:00:00.000Z",
  "docs": [
    {
      "id": "a3f8c1e9b2d4Xk9mPq2vLwR7",
      "text": "Vue 3 手册",
      "link": "/handbook/frontend/vue3-handbook",
      "group": "前端开发"
    }
  ]
}
```

构建时由 `gen-doc-list.mjs` 从 sidebar 生成，输出到 `public/doc-list.json`。

### 3.5 增删检测逻辑（基于 docId 匹配）

- **新增文档**：doc-list 中的 `id` 在 IDB 中无对应记录 → 自动创建空记录
- **删除文档**：IDB 中的 `docId` 在 doc-list 中无对应 → 标记 `isArchived = true`
- **恢复文档**：archived 的 id 重新出现 → 取消归档
- **URL/标题变更**：同一 docId 但 link/text 变了 → 更新字段，历史不受影响
- **旧记录修复**：无 docId 的旧记录 → `stripBase(url)` 查找 docId 并补全

## 四、自动学习感知设计

### 4.1 核心流程

```
页面加载 / 路由切换
    ↓
stripBase(url) → 查找 docId → 不在清单中？跳过
    ↓
从 IDB 恢复已累计秒数 → 已达标？直接触发
    ↓
启动 10s 定时器（仅 visibilityState === 'visible' 时累加）
    ↓
visibilitychange 事件：隐藏 → 持久化 + 停止，恢复 → 重启
    ↓
累计 ≥ 600 秒 → 自动注册「已学习」→ 触发 FSRS 首次调度
    ↓
停止计时（不再重复触发）
```

### 4.2 关键设计决策

| 决策点   | 方案                             | 理由                             |
| -------- | -------------------------------- | -------------------------------- |
| 计时粒度 | 10s tick，仅 visible 时累加      | 简单可靠，不需要高精度           |
| 事件驱动 | visibilitychange 停止/重启 timer | 后台零唤醒，比 tick 内检查更高效 |
| 累计策略 | 同一页面多次进入时间累加         | 用户可能分多次阅读同一篇文档     |
| 路由切换 | 停止旧 → 持久化 → 开始新         | 避免跨页面误计                   |
| 重复触发 | 已标记 autoLearnedAt 不重复触发  | 避免重复调度                     |

### 5.1 双模式算法

// FSRS（默认，推荐）
const scheduler = fsrs({
  request_retention: 0.9, // 目标保持率 90%

// 经典艾宾浩斯（固定间隔）

### 5.2 复习评分映射

| 用户操作  | FSRS Rating | 含义             | 对调度的影响              |
| --------- | ----------- | ---------------- | ------------------------- |
| 😟 忘了   | `Again`     | 完全不记得       | 间隔重置，进入 relearning |

## 七、VitePress 适配

### 7.1 URL 规范化（stripBase）

运行时 URL 与 doc-list.json 存在三处差异，`stripBase()` 统一处理：

```
输入: https://jinnianwushuang.github.io/smart-code-tool/interview/react/xxx.html
  ① 剥离域名:    /smart-code-tool/interview/react/xxx.html
  ② 剥离 base:   /interview/react/xxx.html
  ③ 剥离 .html:  /interview/react/xxx
输出: /interview/react/xxx  ✅ 匹配 doc-list.json
```

### 7.2 URL 存储与导航

- **存储**：`useCurrentPage` → `stripBase(window.location.pathname)` → 与 doc-list 一致
- **导航**：`navigateTo` → 路径格式 URL 加回 `import.meta.env.BASE_URL` → `router.go(fullPath)`
- **旧数据**：完整 URL 在 `navigateTo` 中通过 `new URL()` 提取 pathname 处理

### 7.3 favicon 修复

// config.js — 使用绝对路径，VitePress 自动补全 base
