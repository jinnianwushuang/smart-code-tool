## 一、技术调研结论

### 1.1 开源间隔重复算法方案对比

| 方案                                                  | 核心特点                                                              | 优势                                                                                    | 劣势                                                                             | 适用性评估                         |
| ----------------------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------- |
| **ts-fsrs** (Free Spaced Repetition Scheduler)        | 基于机器学习的三变量记忆模型（难度/稳定性/可提取性），Anki 新一代算法 | 科学精准，比 SM-2 减少 20-30% 复习量；TypeScript 原生，支持 ESM/CJS/UMD；npm 周活跃维护 | 面向闪卡场景设计（Front/Back），需要适配"文档复习"场景；参数优化需要一定数据积累 | ⭐⭐⭐⭐⭐ 核心算法引擎            |
| **SM-2** (SuperMemo 2)                                | 经典间隔重复算法，Anki 旧版默认                                       | 简单成熟，实现成本低                                                                    | 固定系数，不区分个体差异，效率低于 FSRS                                          | ⭐⭐⭐ 备选方案                    |
| **固定艾宾浩斯间隔** (5min→30min→12h→1d→2d→4d→7d→15d) | 按需求文档中的固定时间节点                                            | 完全符合用户原始需求描述，零依赖                                                        | 不个性化，无法根据掌握程度动态调整                                               | ⭐⭐⭐⭐ 作为 FSRS 的降级/入门方案 |

**结论**：采用 **ts-fsrs 作为核心算法引擎**，同时保留固定间隔作为"经典模式"可选项。ts-fsrs 纯计算库，无 UI 依赖，体积极小（~15KB gzip），完美适配浏览器环境。

### 1.2 IndexedDB 持久化方案对比

| 方案                        | 体积           | 特点                                                | 适用场景               |
| --------------------------- | -------------- | --------------------------------------------------- | ---------------------- |
| **idb-keyval**              | ~600B (brotli) | 极简 key-value API，Jake Archibald 维护             | 键值存储，无需复杂查询 |
| **idb**                     | ~1.2KB         | 原生 IndexedDB API 的 Promise 化封装，支持索引/事务 | 需要索引和范围查询     |
| **Dexie.js**                | ~15KB          | 类 ORM 语法，链式查询，版本迁移                     | 中大型应用             |
| **localStorage** (现有方案) | 0              | 同步 API，5MB 限制                                  | 当前 QuickTools 使用   |

**结论**：采用 **idb-keyval** 作为主存储层。理由：

- 复习数据本质是 `Map<docUrl, ReviewRecord>` 的键值结构
- 体积极小，不增加包体积负担
- 容量远超 localStorage（数百 MB vs 5MB），可支撑数千条文档复习记录
- 支持异步操作，不阻塞 UI
- 若后续需要复杂查询（如按状态筛选、统计报表），可平滑升级到 `idb` 或 `Dexie.js`

## 二、整体架构设计

### 2.0 核心设计理念：自动感知，零操作

**学习行为自动检测**：用户在一个页面停留 ≥ 10 分钟（有效阅读时间），系统自动记录为「已学习」，无需任何手动操作。后续复习按调度算法自动排期。

```
用户阅读文档（正常浏览）
  ↓ 页面停留 ≥ 10 分钟（自动感知，无需点击）
系统自动记录「已学习」→ 触发调度引擎计算首次复习时间
  ↓
到期提醒 → 用户自评（忘了/有印象/记得/秒记）→ 计算下次复习时间
  ↓
循环直到转入长期记忆
```

**有效时间判定规则**：

- 页面 `visibilityState === 'visible'` 时才计时（切换 Tab / 最小化不计）
- SPA 路由切换时自动重置计时器（新页面重新开始累计）
- 支持累计计时：同一页面多次进入，时间累加（如看了 5 分钟 → 切走 → 回来看 5 分钟 = 10 分钟）
- 达到阈值后自动写入，不重复触发

## 三、数据模型设计

### 3.1 IndexedDB 存储结构

使用 idb-keyval 的自定义 store 模式，逻辑上分为三个命名空间：

```
IndexedDB: "quick-tools-db"
├── Store: "keyval"
│   ├── "review:records"     → ReviewRecord[]   (所有文档的复习记录)
│   ├── "review:docSnapshot"  → DocSnapshot       (最近一次文档清单快照)
│   ├── "review:settings"     → UserSettings      (用户配置)
│   └── "review:stats"        → ReviewStats       (统计数据)
```

### 3.2 核心数据结构

```typescript
// ── 复习记录（每个文档一条，以 docId 为主键）──
interface ReviewRecord {
  docId: string; // 文档稳定 ID（与 sidebar 中的 id 字段对应，如 'a3f8c1e9b2d4Xk9mPq2vLwR7'）
  url: string; // 文档路径（可从 doc-list 同步更新，不影响历史记录）
  title: string; // 文档标题（可以从 doc-list 同步更新，不影响历史记录）
  group: string; // 所属分组（从 sidebar 提取），如 "前端开发"

  // ── 自动学习感知字段 ──
  autoLearnedAt: string | null; // 自动标记「已学习」的时间（首次停留达标时）
  accumulatedSeconds: number; // 累计有效阅读秒数（用于展示进度）

  // ── FSRS 调度字段 ──
  state: "new" | "learning" | "review" | "relearning";
  stability: number; // 记忆稳定性
  difficulty: number; // 难度
  due: string; // 下次到期时间 (ISO 8601)
  lastReview: string | null; // 上次复习时间

  // ── 学习历史（完整时间线）──
  reviewCount: number; // 总复习次数
  lapses: number; // 遗忘次数（从 review 退回 relearning）
  history: LearningLogEntry[]; // 完整学习历史（自动学习 + 每次复习），上限 50 条

  // ── 元数据 ──
  createdAt: string; // 首次加入时间
  updatedAt: string; // 最后更新时间
  isArchived: boolean; // 是否已归档（文档被删除时标记）
  isDismissed: boolean; // 是否被标记为「已知」（从盲区移除，不参与调度）
}

// ── 学习历史条目（完整时间线，含自动学习 + 每次复习）──
interface LearningLogEntry {
  timestamp: string; // 事件时间 (ISO 8601)
  type: "auto-learn" | "review"; // 事件类型
  // ── auto-learn 事件字段 ──
  accumulatedSeconds?: number; // 累计阅读秒数（仅 auto-learn 有）
  // ── review 事件字段 ──
  rating?: "again" | "hard" | "good" | "easy"; // 复习评分（仅 review 有）
  interval?: number; // 本次间隔天数（仅 review 有）
  elapsedDays?: number; // 实际经过天数（仅 review 有）
}

// ── 文档快照（用于检测增删） ──
interface DocSnapshot {
  version: number; // 快照版本号
  updatedAt: string; // 快照时间
  docs: Array<{
    url: string;
    title: string;
    group: string;
  }>;
}

// ── 用户配置 ──
interface UserSettings {
  algorithm: "fsrs" | "ebbinghaus"; // 算法模式
  requestRetention: number; // 目标保持率 (0.0-1.0)，默认 0.9
  maximumInterval: number; // 最大间隔（天），默认 365
  dailyReviewLimit: number; // 每日复习上限，默认 50
  historyLimitPerDoc: number; // 单文档学习历史上限，默认 50
  enableNotification: boolean; // 是否开启浏览器通知提醒
}
```

### 3.3 Sidebar 菜单模型增强：文档 ID 锚定

**核心问题**：文档目录调整、文件重命名、标题修改都会导致 `link` / `text` 变化，如果用 URL 作为复习记录的锚点，一旦变更就会丢失历史数据。

**解决方案**：在每个带 `link` 的叶子菜单项中新增 `id` 字段作为**稳定锚点**。

#### 3.3.1 Sidebar 菜单项模型升级

**文件头部约束注释**（新增到每个 sidebar 文件顶部，告知 AI 和开发者必须生成 id）：

```javascript
/**
 * ⚠️ AI / 开发者须知：
 * 每个带 link 的叶子菜单项必须包含 id 字段（24 位 nanoid），作为文档的稳定锚点。
 * 新增菜单时请运行: node scripts/inject-sidebar-ids.mjs 自动生成 id
 * id 一旦生成永不修改，即使 text / link 变更也保持原值。
 * VitePress 会忽略 id 字段，不影响解析。
 */
```

**菜单项模型**：

```javascript
// 升级前
{ text: 'Vue 3 手册', link: '/handbook/frontend/vue3-handbook' }

// 升级后（新增 id 字段）
{ text: 'Vue 3 手册', link: '/handbook/frontend/vue3-handbook', id: 'a3f8c1e9b2d4Xk9mPq2vLwR7' }
```

**约束**：

- `id` 仅加在带 `link` 的叶子节点上，分组节点（只有 `text` + `items`）不加
- VitePress 会忽略不认识的字段，不影响解析和渲染
- `id` 一旦生成永不修改，即使 `text` / `link` 变化也保持原值

#### 3.3.2 ID 格式

采用 **24 字符 nanoid**（URL 安全的 base64url 编码）：

| 特性     | 值                            |
| -------- | ----------------------------- |
| 长度     | 24 字符（约 143 bit 信息熵）  |
| 碰撞概率 | 10 万条文档下碰撞概率 < 10⁻³⁶ |
| 格式     | `a-zA-Z0-9_-`，URL 安全       |
| 示例     | `a3f8c1e9b2d4Xk9mPq2vLwR7`    |

选择 24 字符 nanoid 而非 UUID v4 的理由：更短（24 vs 36 字符）、信息熵足够高（143 bit）、可读性更好、URL 安全。

#### 3.3.3 ID 自动生成脚本

编写 `scripts/inject-sidebar-ids.mjs`：

```javascript
// 核心逻辑：
// 1. 读取所有 sidebar/*.js 文件
// 2. 递归遍历，找到带 link 但无 id 的叶子节点
// 3. 为其生成 24 字符 nanoid 并写回文件
// 4. 已有 id 的节点保持不变（幂等）
```

**触发时机**：

- 手动执行：`node scripts/inject-sidebar-ids.mjs`
- 新增文档后手动运行（或未来集成到 git pre-commit hook）
- 与 `gen-doc-list.mjs` 配合：生成 doc-list 时如果发现有节点无 id，自动补充

### 3.4 文档清单获取策略

利用 VitePress sidebar 配置作为文档清单的**唯一数据源**：

```
构建时（VitePress dev server / build）
  ↓
读取 sidebar/*.js → 递归提取所有 { id, text, link } → 生成 doc-list.json
  ↓ 输出到 public/doc-list.json（构建时自动包含在静态资源中）
运行时（浏览器）
  ↓
fetch('/smart-code-tool/doc-list.json') → 获取全站文档清单
  ↓
与 IndexedDB 中的记录对比（按 id 匹配）→ 检测新增 / 删除 / 废弃 / URL 变更
```

**增删检测逻辑（基于 id 匹配）**：

- **新增文档**：doc-list 中的 `id` 在 IndexedDB 中无对应记录 → 自动加入待学习队列
- **删除文档**：IndexedDB 中的 `docId` 在 doc-list 中无对应 id → 标记 `isArchived = true`
- **恢复文档**：之前 archived 的 id 重新出现在 doc-list 中 → 取消归档，保留历史
- **URL 变更**：同一个 `id` 但 `link` 变了 → 更新 `url` 字段，保留全部复习历史（核心优势！）
- **标题变更**：同一个 `id` 但 `text` 变了 → 更新 `title` 字段，历史不受影响

## 四、自动学习感知设计（useAutoLearn）

### 4.0 核心流程

```
┌────────────────────────────────────────────────────────────────────┐
│                     useAutoLearn 生命周期                           │
│                                                                    │
│  页面加载 / 路由切换                                                │
│      ↓                                                             │
│  初始化计时器（从 IndexedDB 读取该页面已累计的秒数）                  │
│      ↓                                                             │
│  开始计时（每秒 +1，仅 visibilityState === 'visible' 时）           │
│      ↓                                                             │
│  ┌─ 用户切走 Tab → 暂停计时 ─┐                                     │
│  │  用户切回 Tab → 恢复计时   │                                     │
│  └────────────────────────────┘                                     │
│      ↓                                                             │
│  累计秒数 ≥ 600（10 分钟）                                          │
│      ↓                                                             │
│  自动注册「已学习」→ 写入 autoLearnedAt → 触发 FSRS 首次调度         │
│      ↓                                                             │
│  显示轻量提示：「📖 已自动记录学习，将在 X 天后提醒复习」             │
│      ↓                                                             │
│  停止计时（该页面不再重复触发）                                      │
└────────────────────────────────────────────────────────────────────┘
```

### 4.1 useAutoLearn.js 核心逻辑

```javascript
// composables/useAutoLearn.js
import { ref, onMounted, onUnmounted, watch } from "vue";
import { useRouter } from "vitepress";

const AUTO_LEARN_THRESHOLD = 600; // 10 分钟 = 600 秒
const TICK_INTERVAL = 1000; // 每秒 tick 一次

export function useAutoLearn(getPage, storage) {
  const accumulatedSeconds = ref(0); // 当前页面累计有效秒数
  const isAutoLearned = ref(false); // 当前页面是否已自动标记
  const progressPercent = computed(() =>
    Math.min(
      100,
      Math.round((accumulatedSeconds.value / AUTO_LEARN_THRESHOLD) * 100),
    ),
  );

  let timer = null;
  let currentUrl = "";

  // ── 页面进入时：加载已累计时间，开始计时 ──
  const startTracking = async (url) => {
    currentUrl = url;
    const record = await storage.getRecord(url);
    // 如果已自动标记过，则跳过
    if (record?.autoLearnedAt) {
      isAutoLearned.value = true;
      return;
    }
    accumulatedSeconds.value = record?.accumulatedSeconds ?? 0;
    timer = setInterval(tick, TICK_INTERVAL);
  };

  // ── 每秒 tick：仅可见时累加 ──
  const tick = () => {
    if (document.visibilityState !== "visible") return;
    accumulatedSeconds.value++;
    if (accumulatedSeconds.value >= AUTO_LEARN_THRESHOLD) {
      onAutoLearned();
    }
  };

  // ── 达到阈值：自动注册 ──
  const onAutoLearned = async () => {
    clearInterval(timer);
    timer = null;
    isAutoLearned.value = true;
    const { url, title } = getPage();
    await storage.markAutoLearned(url, {
      title,
      accumulatedSeconds: accumulatedSeconds.value,
    });
    // 可选：显示轻量提示
  };

  // ── 路由切换：停止旧计时，开始新页面 ──
  const onRouteChange = (newUrl) => {
    stopTracking();
    startTracking(newUrl);
  };

  // ── 页面离开：持久化累计秒数 ──
  const stopTracking = () => {
    if (timer) clearInterval(timer);
    timer = null;
    if (!isAutoLearned.value && accumulatedSeconds.value > 0) {
      storage.saveAccumulatedSeconds(currentUrl, accumulatedSeconds.value);
    }
  };

  // ── 可见性变化监听 ──
  // 无需额外处理：tick 中已判断 visibilityState
  // 切走时不计入，切回时自动恢复

  return {
    accumulatedSeconds,
    isAutoLearned,
    progressPercent,
    startTracking,
    stopTracking,
    onRouteChange,
  };
}
```

### 4.2 挂载位置

`useAutoLearn` 需要在 **每个页面全局运行**，挂载在 `QuickTools.vue` 的 `setup` 中（QuickTools 已通过 Layout.vue 的 `layout-bottom` slot 全局注入到每个页面）：

```javascript
// QuickTools.vue setup 中新增
const autoLearn = useAutoLearn(getPage, reviewStorage);

// 监听路由变化
const router = useRouter();
router.onAfterRouteChanged = (to) => {
  autoLearn.onRouteChange(to);
};

onMounted(() => {
  autoLearn.startTracking(window.location.pathname);
});
onUnmounted(() => {
  autoLearn.stopTracking();
});
```

### 4.3 关键设计决策

| 决策点   | 方案                                     | 理由                                 |
| -------- | ---------------------------------------- | ------------------------------------ |
| 计时粒度 | 每秒 tick，仅 visible 时 +1              | 简单可靠，不需要高精度               |
| 累计策略 | 同一页面多次进入时间累加                 | 用户可能分多次阅读同一篇文档         |
| 路由切换 | 停止旧页面计时 → 持久化累计 → 开始新页面 | 避免跨页面误计                       |
| Tab 切换 | 通过 `visibilityState` 自动暂停/恢复     | 零额外代码，浏览器原生支持           |
| 阈值可配 | 默认 10 分钟，设置中可调                 | 不同文档长度不同，长文档可能需要更久 |
| 重复触发 | 已标记 autoLearnedAt 的页面不再重复触发  | 避免重复调度                         |

## 五、调度引擎设计

### 5.1 双模式算法支持

```javascript
// scheduler.js
import { fsrs, createEmptyCard, Rating } from "ts-fsrs";

// ── 模式一：FSRS（默认，推荐） ──
const scheduler = fsrs({
  request_retention: 0.9, // 目标保持率 90%
  maximum_interval: 365, // 最大间隔 365 天
  enable_fuzz: true, // 长间隔添加随机抖动，避免扎堆
});

// 复习调度
function scheduleReview(card, rating) {
  const result = scheduler.next(card, new Date(), Rating[rating]);
  return { card: result.card, log: result.log };
}

// ── 模式二：经典艾宾浩斯（固定间隔） ──
const EBBINGHAUS_INTERVALS = [
  5 / 1440, // 5 分钟
  30 / 1440, // 30 分钟
  0.5, // 12 小时
  1, // 1 天
  2, // 2 天
  4, // 4 天
  7, // 7 天
  15, // 15 天
];

function scheduleEbbinghaus(reviewCount) {
  const days = EBBINGHAUS_INTERVALS[reviewCount] ?? 30;
  return { due: addDays(new Date(), days), interval: days };
}
```

### 5.2 复习评分映射

| 用户操作  | FSRS Rating | 含义             | 对调度的影响                    |
| --------- | ----------- | ---------------- | ------------------------------- |
| 😟 忘了   | `Again`     | 完全不记得       | 间隔重置为最短，进入 relearning |
| 😐 有印象 | `Hard`      | 勉强想起来       | 间隔略微缩短                    |
| 🙂 记得   | `Good`      | 有一定犹豫后想起 | 正常间隔推进（默认路径）        |
| 😎 秒记   | `Easy`      | 毫不费力         | 间隔大幅延长                    |

### 5.3 到期检测与提醒

```javascript
// 获取今日待复习列表
function getDueReviews(records) {
  const now = new Date();
  return records
    .filter((r) => !r.isArchived && new Date(r.due) <= now)
    .sort((a, b) => new Date(a.due) - new Date(b.due));
}

// 浏览器通知提醒（可选）
function notifyDueReview(dueCount) {
  if (!("Notification" in window)) return;
  if (Notification.permission === "granted") {
    new Notification("📚 复习提醒", {
      body: `你有 ${dueCount} 篇文档到期需要复习`,
      icon: "/logo/icons8-light-on-96.png",
    });
  }
}
```
