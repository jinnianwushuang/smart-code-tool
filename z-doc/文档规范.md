# 文档规范

> 本文档定义站点所有 Markdown 文档 和 Vue 组件的编写规范。
> AI 助手和开发者在新增或修改文档/组件时必须遵循本规范。

---

## 1. Frontmatter 规范

每篇 Markdown 文档**必须**在文件首行包含 YAML frontmatter 块。

### 1.1 基本格式

```yaml
---
title: '文档标题'
tags: ['标签1', '标签2']
---
```

### 1.2 字段说明

| 字段    | 必填 | 类型     | 说明                                                   |
| ------- | ---- | -------- | ------------------------------------------------------ |
| `title` | ✅   | `string` | 文档标题，与 H1 标题一致或语义等价                     |
| `tags`  | ✅   | `array`  | 标签字符串数组，反映文档核心技术主题，用于快捷工具筛选 |
| `order` | ❌   | `number` | 排序权重（仅在 sidebar 需要特定排序时使用）            |

### 1.3 禁止字段

| 字段      | 说明                                                                                                                                                            |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `updated` | ❌ 禁止使用。VitePress 的「最后更新时间」读取 git 提交时间，frontmatter 中的 `updated` 无效且冗余。新增文档时不要添加此字段；更新文档时若发现此字段应直接删除。 |

### 1.4 Tags 约束

- **数量**：1-5 个标签，**建议 1-2 个为宜**，不宜过多
- **长度**：每个标签 2-10 个字符
- **命名**：使用技术领域的通用名称，如 `React`、`Vue`、`设计模式`、`心理学`
- **优先级**：核心技术 > 所属领域 > 文档类型
- **去重**：标签间不应语义重复（如不应同时出现 `前端` 和 `Frontend`）
- **更新时核对**：每次修改文档内容时，应检查 tags 是否仍然准确；若主题已变化需同步调整 tags，保持精简

**示例**：

```yaml
# 好的 tags
tags: ['React', 'Hooks']
tags: ['心理学', '认知']
tags: ['设计模式', '架构']
tags: ['Vue']

# 不好的 tags
tags: [] # ❌ 空数组，至少 1 个
tags: ['a', 'b'] # ❌ 单字符，无意义
tags: ['React'] # ✅ 一个标签完全没问题
tags: ['前端', 'Frontend'] # ❌ 语义重复
tags: ['a', 'b', 'c', 'd', 'e', 'f'] # ❌ 过多，建议精简到 1-2 个
```

### 1.4 完整示例

```markdown
---
title: 'React Memo 与自动跳过'
tags: ['React', '性能优化', '编译时']
---

# React Memo 与自动跳过

正文内容...
```

## 2. 标题规范

- 文件第一个 H1（`# 标题`）应与 frontmatter `title` 语义一致
- H1 后紧跟简短描述（1-2 句话说明文档核心价值）
- 章节使用 H2（`##`）起始，逐级递增，不跳级

---

## 3. 文件命名

- 使用 `kebab-case`（小写 + 连字符），如 `react-memo.md`
- 中文目录下的文件可用中文命名，如 `组件系统.md`
- 避免空格和特殊字符

---

## 4. 内容质量

- **结构清晰**：章节划分合理，每节有明确主题，避免大段无标题文字
- **无 AI 对话残留**：禁止出现「您想了解…吗？」「让我们继续」「接下来我们…」等 AI 对话提示词或引导语
- **自包含**：文档应独立完整，不依赖对话上下文，读者无需追问即可理解全部内容
- **语言简洁**：避免冗余的过渡句和客套话，直接表达技术内容

---

## 5. 自动化

- `scripts/gen-doc-list.mjs` 自动提取 frontmatter tags
- 无 frontmatter tags 时，从 URL 路径推导（兜底逻辑）
- 自动从 git 历史提取每个文档的 `createdAt`（首次提交时间）和 `updatedAt`（最后提交时间）
- 时间字段写入 `doc-list.json`，供快捷工具的「近期更新」和卡片时间显示使用
- 运行 `node scripts/gen-doc-list.mjs` 重新生成 `docs/public/doc-list.json`
- `scripts/inject-sidebar-ids.mjs` 自动为 sidebar 菜单项注入 id

---

## 6. 新增文档必做步骤

> **每次新增文档时，以下步骤为固定流程，必须全部完成。**

### 6.1 文档本身

- [ ] 文件首行包含 frontmatter（title + tags）
- [ ] tags 精简（1-5 个，建议 1-2 个）
- [ ] 内容结构清晰，无 AI 对话残留

### 6.2 入口与菜单

- [ ] 添加到对应 sidebar 配置文件（`docs/.vitepress/config/sidebar/`）
- [ ] sidebar 菜单项包含 `id` 字段（24 位 nanoid）
- [ ] 更新对应的入口文件（如 `architecture-document/index.md`）
- [ ] 如涉及跨框架概念，更新 `terminology-index.md`

### 6.3 自动生成

- [ ] 执行 `pnpm gen:doc-list` 重新生成 `docs/public/doc-list.json`

---

## 7. 检查清单

新增文档时确认：

- [ ] 文件首行是 `---`（frontmatter 开始）
- [ ] 包含 `title` 字段
- [ ] 包含 `tags` 字段（字符串数组，1-5 个标签，建议 1-2 个）
- [ ] frontmatter 以 `---` 结束
- [ ] 已添加到对应 sidebar 配置文件
- [ ] sidebar 菜单项包含 `id` 字段（24 位 nanoid）

更新文档时确认：

- [ ] 检查 tags 是否仍然准确，主题变化时同步调整
- [ ] tags 数量不超过 5 个，保持精简（1-2 个为宜）

## 8. 时间与时区规范

项目中有两种时间来源，显示时必须区分处理，否则会出现时区偏差（如 UTC 时间比北京时间少 8 小时）。

### 8.1 两种时间来源

| 来源           | 格式示例                     | 时区                   | 产生方式                                 |
| -------------- | ---------------------------- | ---------------------- | ---------------------------------------- |
| **git 时间戳** | `"2026-10-07 00:42:01"`      | 本地时间（无时区信息） | `gen-doc-list.mjs` 从 `git log` 提取     |
| **运行时生成** | `"2026-10-09T14:30:25.000Z"` | UTC（ISO 8601）        | `new Date().toISOString()`、用户操作记录 |

### 8.2 显示规则

- **git 时间戳**（`createdAt` / `updatedAt`）：已是本地时间，可直接显示，也可通过 `formatTimestamp()` 统一格式
- **ISO 时间戳**（`visitedAt` / `time` 等）：**禁止直接截取字符串显示**，必须经过本地时间转换
- **统一工具函数**：`utils.js` 中的 `formatTimestamp(ts)` 自动识别两种格式并输出本地时间 `YYYY-MM-DD HH:mm:ss`
- **日期部分提取**：使用 `formatDatePart(ts)` 获取本地日期 `YYYY-MM-DD`，不要用 `.slice(0, 10)` 截取 ISO 字符串
- **今日判断**：使用 `todayStr()` 获取本地今天日期，不要用 `new Date().toISOString().slice(0, 10)`（得到的是 UTC 日期）

### 8.3 常见陷阱

```js
// ❌ 错误：直接截取 ISO 字符串，显示的是 UTC 时间
isoStr.replace('T', ' ').slice(0, 19) // 得到 UTC 时间
record.visitedAt?.slice(0, 10) // 得到 UTC 日期

// ✅ 正确：使用工具函数转本地时间
formatTimestamp(isoStr) // 本地时间 YYYY-MM-DD HH:mm:ss
formatDatePart(isoStr) // 本地日期 YYYY-MM-DD
todayStr() // 本地今天日期
```

### 8.4 dayjs 处理

`dayjs()` 解析 ISO 字符串时会自动转为本地时间，因此 NoteTab/DoubtTab/ProgressTab 中使用 `dayjs(record.time).format(...)` 的写法是正确的，无需额外处理。

## 9. Vue 组件规范

### 9.1 代码块顺序

所有 Vue 单文件组件（SFC）必须按以下顺序组织代码块：

```
1. <template>     — 模板
2. <script setup> — 逻辑
3. <style scoped> — 样式（如有）
```

各区块之间用空行分隔。

### 9.2 UI 组件库

VitePress 主题侧（`docs/.vitepress/theme/`）使用 **Element Plus** 作为 UI 组件库。

**已集成配置**：

- `docs/.vitepress/theme/index.js`：全量注册 Element Plus + 亮/暗色 CSS
- `docs/.vitepress/config/vite.js`：`unplugin-vue-components` 按需自动导入

**使用规则**：

- 优先使用 `el-*` 组件，避免手写自定义按钮/卡片/输入框/弹窗等
- 常用组件：`el-button`、`el-card`、`el-tag`、`el-input`、`el-select`、`el-dialog`、`el-tabs`、`el-empty`、`el-badge`、`el-slider`、`el-switch`
- 暗色模式由 `element-plus/theme-chalk/dark/css-vars.css` 自动适配 VitePress 的 `.dark` class
- 自定义 CSS 只保留布局/间距，视觉样式交给组件库
- **最小字号 14px**：快捷工具内所有文本不得低于 14px（PC 端为主）

### 9.3 快捷工具组件架构

```
docs/.vitepress/theme/components/
├── QuickTools.vue              # 主入口（el-dialog + el-tabs）
├── BackToTop.vue               # 回到顶部
└── quick-tools/
    ├── composables/            # 业务逻辑层（use*.js）
    ├── tabs/                   # 各 Tab 页面组件
    │   ├── ReviewTab.vue       # 复习（el-tabs/el-card/el-slider/el-select）
    │   ├── RecentUpdatesTab.vue # 近期更新（统计卡片 + 按天过滤）
    │   ├── ProgressTab.vue     # 进度（el-button/el-card/el-tag）
    │   ├── DoubtTab.vue        # 疑惑（el-input/el-button/el-card）
    │   ├── NoteTab.vue         # 笔记（同 DoubtTab 模式）
    │   └── LearningStreakTab.vue # 学习实况（日历热力图 + 连续打卡）
    └── shared/                 # 跨模块共享
        ├── TagFilter.vue       # 标签筛选器（el-dialog + el-tag chips）
        ├── quick-tools.css     # 布局样式（仅布局，不含视觉样式）
        ├── useDocIdMapper.js   # docId 映射
        ├── useQtStorage.js     # IndexedDB 存储
        └── utils.js            # 工具函数
```
