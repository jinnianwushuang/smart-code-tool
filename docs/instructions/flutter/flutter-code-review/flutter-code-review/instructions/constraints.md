# 指令约束 — AI 执行边界

> 以下约束为硬性规则，AI 执行过程中不可违反。

## 1. 单次执行约束

- **一次只能执行一类任务类型**
- 禁止混合执行多种任务
- 若用户提交包含多种任务类型的请求，必须拆分为多次独立执行

## 2. 存疑即问约束

- 任务信息不全或存在疑义时，**必须暂停执行并向使用者提问确认**
- 提问时需**给出建议选项**（至少 2 个）或直接让使用者给出方案
- **禁止瞎猜、禁止脑补**

## 3. 安全熔断约束

- 任务不在指令集有效范围内时，**必须停止执行**并告知原因
- 执行过程中遇到无法解决的卡点时，**必须主动停止**并列出卡点清单
- **禁止强行编造或跳过问题**

## 4. 检查范围约束

- 默认遵循项目 `.gitignore` 排除规则
- 可通过任务命令指定检查目录，未指定则全项目扫描（聚焦 `lib/`）
- `config.md` 中的 `exclude_dirs` / `exclude_files` 在 `.gitignore` 基础上额外排除
- 生成文件（`*.g.dart` / `*.freezed.dart`）默认不纳入人工审查
- **不得检查被排除的目录和文件**

## 5. 报告规范约束

- 报告文件名必须包含时间戳：`{任务类型}_{检查目标}_{YYYY-MM-DD-HH-mm-ss}.md`
- 每条问题必须标注严重级别：🔴 Error / 🟡 Warning / 🔵 Info
- 如存在上次报告，必须追加对比章节
- 每次检查后必须更新 `_index.md` 总表

## 6. 静态分析检查为建议性质

- `analysis_options.yaml` 检查**仅给出建议**，不自动修改项目配置
- 除非用户明确要求修改，否则只输出建议

## 7. 不可跳过的步骤

以下步骤在任何任务中都**不可跳过**：

- 门禁检查（gate-check.md）
- 信息完整性检查
- 报告生成
- 报告总表更新

## 8. 代码生成约束

- 检查过程中不修改任何源代码
- 仅输出检查报告和建议
- 除非用户明确要求修复，否则不自动修改代码
