# 任务：修复

> 修复页面中的 Bug 或异常行为。

## 执行步骤

### 1. 定位问题

```
1. 理解问题描述（错误信息、复现步骤、预期行为）
2. 读取相关代码文件，定位问题根因
3. 判断问题类型：
   - 状态管理问题（Rx 变量未正确更新、Obx 粒度过大）
   - 生命周期问题（onClose 未清理、build 内 Get.put）
   - 路由问题（参数传递错误、Binding 未注册）
   - UI 问题（const 缺失导致不必要重建、Widget 组合错误）
   - API 请求问题（参数错误、异常未处理）
4. 如有歧义，触发「存疑即问」
```

### 2. 制定修复方案

```
1. 说明问题根因
2. 提出修复方案（至少 1 个，复杂问题给出 2 个选项）
3. 评估修复影响范围
```

### 3. 执行修复

```
1. 修改目标代码
2. 确保修复不引入新问题
3. 检查是否有同类问题需要一并修复
```

### 4. 验证修复

```
→ 执行 common-steps.md 中的步骤 D（静态分析自检）
→ 确认修复后代码符合架构规范
```

### 5. 输出报告

```
→ 执行 common-steps.md 中的步骤 E（输出执行报告）
→ 额外列出：问题根因分析、修复方案说明、是否有同类问题
```

## 完成标准

- [ ] 问题根因已定位并修复
- [ ] 修复未引入新问题
- [ ] 代码符合架构规范
- [ ] 执行报告已输出
