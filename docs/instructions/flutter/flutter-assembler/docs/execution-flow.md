## 各步骤详解

### 步骤 1：读取上下文

AI 按 `entry/context-entry.md` 中定义的顺序加载文件：

1. `config.md` → 获取项目路径、技术栈、编码规范等配置
2. `glossary.md` → 统一术语理解
3. `architecture/` → 按需读取架构参照文件
4. `instructions/` → 加载执行框架

### 步骤 2：门禁检查

执行 `instructions/gate-check.md` 中定义的 4 类前置检查：

| 检查类型 | 内容 |
|----------|------|
| 配置完整性 | config.md 中必填项是否已填写 |
| 核心文件存在性 | 路由配置、主题配置、API 客户端是否存在 |
| 任务信息 | 用户提交的任务信息是否包含必要字段 |
| 依赖检查 | Flutter SDK、get 包等是否满足 |

### 步骤 3：信息完整性检查

判断任务信息是否充分：

- **信息充分** → 继续
- **信息不足** → 暂停，列出问题，给出建议选项，等待回复
- **禁止行为**：瞎猜、脑补需求

### 步骤 4：配置透明化确认（可选）

当 `show_config_before_exec` 为 `true` 时输出配置清单供确认。

### 步骤 5-6：识别并锁定任务类型

| 关键词 | 任务类型 |
|--------|----------|
| 新增、创建、开发、实现 | 新需求开发 |
| 重构、优化、改造、迁移 | 重构 |
| 迭代、修改、调整、增加功能 | 需求迭代 |
| 修复、bug、报错、异常 | 修复 |
| 检查、审查、review、合规 | 代码检查 |

### 步骤 7-9：执行、熔断、复核

按对应任务指令执行，遇阻熔断，完成后复核自检。

## 任务提交格式

```
任务类型：<新需求开发 | 重构 | 需求迭代 | 修复 | 代码检查>
问题描述：<具体描述>
目标目录：<输出目录路径>
报告地址：<报告输出路径 或 默认>
附加信息：<其他补充>
```
