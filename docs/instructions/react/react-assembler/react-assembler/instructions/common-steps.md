# 通用基础步骤

> 各任务类型复用的公共步骤片段。每个任务指令文件在执行过程中引用本文件中的步骤。

## 步骤 A：创建新的页面模块

```
1. 确定模块类型（Hook / 组件 / Action）
2. 确定文件放置位置（参照 architecture/directory-convention.md）
3. 创建文件，按命名规则命名
   - 组件：PascalCase.jsx
   - Hook：kebab-case.js，use- 前缀
   - Action：kebab-case.js，-action 后缀
4. 编写代码，遵循架构参照文件中的标准写法
5. 添加中文注释（比例 ≥ 10%）
6. 确认文件行数未超过约束上限
```

## 步骤 B：修改现有模块

```
1. 读取目标模块文件，理解现有代码
2. 确定修改范围，不影响其他函数/组件
3. 修改代码，遵循命名规范和注释规范
4. 确认修改后文件行数未超过约束上限
5. 确认修改不破坏组件依赖关系
```

## 步骤 C：创建新的组件文件

```
1. 确定组件类型（展示组件 / 容器组件 / 表单组件 / 布局组件）
2. 确定组件放置位置（页面级 components/ 或全局 components/ui/）
3. 创建 PascalCase.jsx 文件
4. 使用函数组件，props 解构获取参数
5. 复杂逻辑抽取到 Hook，组件只负责渲染
6. 编写样式（遵循 CSS 优先级链）
```

## 步骤 D：静态分析自检

```
1. 命名规范检查：组件 PascalCase、Hook camelCase、变量 camelCase
2. Compiler 兼容性检查：无手写 useMemo/useCallback/forwardRef
3. 注释比例检查：注释行数 / 总行数 ≥ 配置值（默认 10%）
4. 文件行数检查：组件 ≤ 200 行、Hook ≤ 300 行
5. 函数行数检查：单函数 ≤ 50 行
6. Hook 规则检查：无条件调用、副作用有清理
7. CSS 复用检查：是否优先使用了框架组件和全局变量
```

## 步骤 E：输出执行报告

```
1. 列出本次任务创建/修改的所有文件
2. 列出每个文件的关键变更
3. 列出静态分析自检结果
4. 如有告警或建议，一并列出
5. 如配置了代码检查报告，保存到指定目录
```
