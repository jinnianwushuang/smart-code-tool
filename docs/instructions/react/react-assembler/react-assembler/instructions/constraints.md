# 指令约束 — AI 执行边界

> 以下约束为硬性规则，AI 执行过程中不可违反。

## 1. 单次执行约束

- **一次只能执行一类任务类型**
- 禁止混合执行多种任务（如同时做新需求开发和代码检查）
- 若用户提交包含多种任务类型的请求，必须拆分为多次独立执行
- 每次执行前必须锁定唯一任务类型

## 2. 存疑即问约束

- 任务信息不全或存在疑义时，**必须暂停执行并向使用者提问确认**
- 提问时需**给出建议选项**（至少 2 个）或直接让使用者给出方案
- **禁止瞎猜、禁止脑补需求**
- 等待使用者回复后才能继续执行

## 3. 安全熔断约束

- 任务不在指令集有效范围内时，**必须停止执行**并明确告知原因及需完善的点
- 执行过程中遇到无法解决的问题卡点时，**必须主动停止**并列出卡点清单
- **禁止强行编造或跳过问题**

## 4. 验证边界约束

- 重构/修改代码完成后，**默认只走静态分析**
- **不主动启动项目运行验证**
- 仅当 config.md 中 `auto_run_verification` 为 `true` 或用户明确要求时才执行运行验证
- 完成静态分析后，**可建议使用者手动启动项目自检**

## 5. React Compiler 约束

- **禁止手写 `useMemo`/`useCallback`**（React Compiler 自动处理）
- **禁止使用 `forwardRef`**（React 19 ref 直接作为 prop）
- **禁止使用 `defaultProps`/`propTypes`**（使用函数默认参数 + JSDoc）
- **禁止使用 class 组件**
- `<Context.Provider>` 简写为 `<Context>`

## 6. CSS 复用约束

- **禁止产生不通用 CSS**
- 写样式前**必须先查阅 config.md 中的项目可用资源清单**
- 遵循优先级链：UI 框架组件 > 插件 > 全局 CSS/变量 > CSS Modules
- 使用全局 CSS 变量前，确认该变量已在 config.md 的 `css_variables` 中列出

## 7. 不可跳过的步骤

以下步骤在任何任务中都**不可跳过**：

- 门禁检查（gate-check.md）
- 信息完整性检查
- 代码规范自检（code-standard.md）
- 复核清单（review-checklist.md）

## 8. 代码生成约束

- 生成的代码必须满足 config.md 中的代码生成约束配置
- 未配置则使用指令集默认值：单组件 ≤ 200 行、单 Hook ≤ 300 行、注释 ≥ 10%、单函数 ≤ 50 行
- 每次生成代码后必须自检是否满足这些约束
