## 各步骤详解

### 步骤 1：读取上下文

AI 按 `entry/context-entry.md` 中定义的顺序加载文件：

1. `config.md` → 获取项目路径、技术栈、编码规范等配置
2. `glossary.md` → 统一术语理解
3. `architecture/` → 按需读取架构参照文件
4. `instructions/` → 加载执行框架（launcher、constraints、gate-check、common-steps）

### 步骤 2：门禁检查

执行 `instructions/gate-check.md` 中定义的 4 类前置检查：

| 检查类型 | 内容 |
|----------|------|
| 配置完整性 | config.md 中必填项是否已填写 |
| 核心文件存在性 | 页面目录、共享组件/Hooks 目录是否存在 |
| 任务信息 | 用户提交的任务信息是否包含必要字段 |
| 依赖检查 | 项目依赖是否满足（React 版本、状态管理库等） |

### 步骤 3：信息完整性检查

判断任务信息是否充分：

- **信息充分** → 继续
- **信息不足** → 暂停执行，列出需要确认的问题，给出建议选项（至少 2 个），等待用户回复
- **禁止行为**：瞎猜、脑补需求

### 步骤 4：配置透明化确认（可选）

当 `config.md` 中 `show_config_before_exec` 为 `true` 时：

1. 合并用户配置与指令集默认值
2. 输出完整配置清单供用户确认
3. 确认通过后继续

### 步骤 5-6：识别并锁定任务类型

根据用户输入中的关键词识别任务类型：

| 关键词 | 任务类型 |
|--------|----------|
| 新增、创建、开发、实现 | 新需求开发 |
| 重构、优化、改造、迁移 | 重构 |
| 迭代、修改、调整、增加功能 | 需求迭代 |
| 修复、bug、报错、异常 | 修复 |
| 检查、审查、review、合规 | 代码检查 |

**一次只能执行一类任务**，若用户提交多种类型请求，必须拆分。

### 步骤 7：选择对应指令执行

每种任务类型对应独立的任务指令文件，各指令文件定义了具体的执行步骤。

### 步骤 8：执行与熔断

执行过程中：

- 遇到无法解决的问题 → **主动停止**
- 列出卡点清单及需要用户提供的内容
- 禁止强行编造或跳过问题

### 步骤 9：复核自检

执行 `instructions/review-checklist.md` 中的自检项：

1. 命名规范
2. 注释规范
3. 代码量约束
4. 架构合规性
5. React Compiler 兼容性
6. Hooks 规则
7. 状态管理
8. CSS 规范
9. 组件规范
10. 完成度

### 输出执行报告

最终输出包含：

- 创建/修改文件清单
- 自检结果（命名、注释、行数、Compiler 兼容、架构合规）
- 建议（如建议手动启动项目自检）

## 任务提交格式

```
任务类型：<新需求开发 | 重构 | 需求迭代 | 修复 | 代码检查>
问题描述：<具体描述>
目标目录：<输出目录路径>
报告地址：<报告输出路径 或 默认>
附加信息：<其他补充>
```
