# 启动器 — AI 执行框架

> AI 接到检查任务后，必须严格按照以下流程执行。

## 标准执行流程

```
步骤 1：读取上下文
  → 读取 config.md（项目配置）
  → 读取 glossary.md（术语表）
  → 读取 check-rules/（按需加载检查维度）
  → 建立完整上下文

步骤 2：门禁检查
  → 执行 gate-check.md 中的前置条件检查
  → 不通过则停止，告知缺失项

步骤 3：信息完整性检查
  → 判断任务信息是否充分
  → 信息不全 → 暂停，向使用者提问确认
  → 禁止瞎猜、禁止脑补

步骤 4：识别并锁定唯一任务类型
  → ESLint 配置审计 → task-eslint-audit.md
  → 深度代码审查 → task-deep-review.md
  → 完整检查 → task-full-review.md
  → 国际化专项检查 → task-i18n-check.md

步骤 5：确定检查范围
  → 任务命令指定了检查目录 → 仅检查该目录
  → 未指定 → 默认全项目扫描
  → 读取 .gitignore 获取排除规则
  → 合并 config.md 中的 exclude_dirs / exclude_files

步骤 6：执行检查
  → 按对应 task-*.md 的步骤执行
  → 逐维度扫描并记录问题

步骤 7：遇阻熔断
  → 遇到无法解决的问题卡点 → 主动停止
  → 列出卡点清单及需要使用者提供的内容

步骤 8：生成检查报告
  → 按报告格式输出结果
  → 报告文件名：{任务类型}_{检查目标}_{YYYY-MM-DD-HH-mm-ss}.md
  → 如存在上次报告，追加对比章节

步骤 9：更新报告总表
  → 更新 _index.md，追加本次检查记录
```

## 任务类型识别规则

| 关键词 | 任务类型 | 对应指令文件 |
|--------|----------|-------------|
| eslint、配置检查、lint | ESLint 配置审计 | task-eslint-audit.md |
| 审查、检查、review、深度 | 深度代码审查 | task-deep-review.md |
| 完整检查、全面检查 | 完整检查 | task-full-review.md |
| 国际化、i18n、多语种 | 国际化专项检查 | task-i18n-check.md |

## 存疑即问

在任何步骤中，如果信息不充分或存在歧义：
1. **立即暂停执行**
2. **列出需要确认的问题**
3. **给出建议选项**（至少 2 个）
4. **等待使用者回复后再继续**

## 安全熔断

以下情况必须停止执行并反馈：
- 任务不在指令集的有效范围内
- 执行过程中遇到无法解决的卡点
- 配置项缺失导致无法继续
- 目标目录不存在且无法推断
