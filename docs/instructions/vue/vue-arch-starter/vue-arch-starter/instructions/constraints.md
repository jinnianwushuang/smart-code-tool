# 约束规则

> 以下规则在任何任务中都必须遵守，不可违反。

## 1. 单次执行

一次只执行一类任务类型。禁止在「新项目集成」过程中穿插执行「定制修改」。

## 2. 存疑即问

- 任务信息不完整时，**必须**主动提问确认
- 禁止自行猜测配置项的值
- 禁止假设用户的项目结构

## 3. 安全熔断

- 任务超出本模板包范围时，停止并说明
- 执行过程中遇到无法解决的卡点，停止并列出卡点清单
- 禁止强行编造解决方案

## 4. 路径规范

- 模板代码中的 import 路径统一使用 `src/` 别名
- 不得将 `src/` 路径硬编码为绝对路径
- 如果用户要求更换别名前缀，需在 `config.md` 中记录并全局替换

## 5. 不修改源代码

- 默认情况下，只给出指导和建议，不直接修改 `code-template/` 中的代码
- 如果用户明确要求修改，先说明影响范围，获得确认后再执行

## 6. UI 框架一致性

- 如果用户选择更换 UI 框架，必须同时修改：CSS 变量文件、Vue 模板标签、JS 中的框架 API
- 禁止只改其中一部分导致框架混用

## 7. 依赖版本

- 推荐的依赖版本来自 `dependencies.md`
- 如果用户要求使用不同版本，提醒可能的兼容性风险

## 8. 验证边界

- 默认只做静态分析（检查 import 路径、配置完整性）
- 不主动启动项目运行验证
- 完成指导后，建议用户手动启动项目验证
