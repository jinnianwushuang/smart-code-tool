# 启动器 — AI 执行框架

> AI 接到任务后，必须严格按照以下流程执行。

## 标准执行流程

```
步骤 1：读取上下文
  → 读取 config.md（项目配置）
  → 读取 architecture/（架构参照）
  → 读取 glossary.md（术语表）
  → 建立完整上下文

步骤 2：门禁检查
  → 执行 gate-check.md 中的前置条件检查
  → 不通过则停止，告知缺失项

步骤 3：信息完整性检查
  → 判断任务信息是否充分
  → 信息不全 → 暂停，向使用者提问确认（给出建议选项或让使用者给出方案）
  → 禁止瞎猜、禁止脑补需求

步骤 4：配置透明化确认（可选）
  → 若 config.md 中 show_config_before_exec 为 true
  → 输出合并后的完整配置清单（用户配置 + 默认值）供使用者确认
  → 确认通过后继续

步骤 5：识别并锁定唯一任务类型
  → 判断任务属于哪种类型：新需求开发 / 重构 / 需求迭代 / 修复 / 代码检查
  → 一次只能执行一类任务类型，禁止混合

步骤 6：任务有效性判定
  → 任务不在指令集有效范围内 → 停止执行，告知原因及需完善的点
  → 任务有效 → 继续

步骤 7：选择对应指令文件并执行
  → 新需求开发 → task-new-feature.md
  → 重构 → task-refactor.md
  → 需求迭代 → task-iteration.md
  → 修复 → task-fix.md
  → 代码检查 → task-code-review.md

步骤 8：遇阻熔断（执行过程中）
  → 遇到无法解决的问题卡点 → 主动停止
  → 列出卡点清单及需要使用者提供的内容
  → 禁止强行编造或跳过

步骤 9：复核
  → 执行 review-checklist.md 中的自检清单
  → 确认所有完成标准已满足
```

## 任务类型识别规则

| 关键词                     | 任务类型   | 对应指令文件        |
| -------------------------- | ---------- | ------------------- |
| 新增、创建、开发、实现     | 新需求开发 | task-new-feature.md |
| 重构、优化、改造、迁移     | 重构       | task-refactor.md    |
| 迭代、修改、调整、增加功能 | 需求迭代   | task-iteration.md   |
| 修复、bug、报错、异常      | 修复       | task-fix.md         |
| 检查、审查、review、合规   | 代码检查   | task-code-review.md |

## 存疑即问

在任何步骤中，如果信息不充分或存在歧义：

1. **立即暂停执行**
2. **列出需要确认的问题**
3. **给出建议选项**（至少 2 个）
4. **等待使用者回复后再继续**

## 安全熔断

以下情况必须停止执行并反馈：

- 任务不在指令集有效范围内
- 执行过程中遇到无法解决的卡点
- 缺少关键文件且无法推断其内容
- 配置项缺失导致无法继续
