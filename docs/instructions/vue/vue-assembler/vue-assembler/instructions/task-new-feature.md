# 新需求开发指令

> 任务类型：新需求开发
> 触发条件：用户需求包含「新增」「创建」「开发」「实现」等关键词

## 前置依赖

- 门禁检查通过（gate-check.md）
- 信息完整性检查通过
- 任务类型已锁定为「新需求开发」

## 执行步骤

### 步骤 1：需求分析

```
1. 明确需求范围：新增什么功能、涉及哪些模块
2. 确定模板类型：多例模板 or 单例模板
   - 需要跨实例共享状态 → 单例模板
   - 每实例独立状态 → 多例模板
3. 列出需要创建/修改的文件清单
4. 如有不确定项 → 触发「存疑即问」
```

### 步骤 2：状态设计

```
1. 分析需要哪些状态变量
2. 确定状态归属：单例状态 / 多例状态 / 计算属性 / 配置
3. 按业务域拆分文件（table / dialog / other）
4. 执行 common-steps.md 步骤 A（创建状态模块文件）
```

### 步骤 3：事件管道设计

```
1. 分析需要哪些用户交互事件
2. 按业务域组织事件处理函数（dialog / table / other）
3. 执行 common-steps.md 步骤 A（创建事件管道模块文件）
```

### 步骤 4：副作用设计（如需要）

```
1. 分析是否需要 watcher、listener、timer 等副作用
2. 确定副作用类型，写入对应的 effect 文件
3. 执行 common-steps.md 步骤 A（创建副作用模块文件）
```

### 步骤 5：组件开发（如需要）

```
1. 确定组件类型和放置位置
2. 执行 common-steps.md 步骤 C（创建组件文件）
3. 声明对接文档（父级提供什么状态、通道、函数）
```

### 步骤 6：生命周期编排

```
1. 更新 lifecycle.js，在对应钩子中调用新创建的函数
2. onBeforeMount：初始化相关
3. onMounted：加载初始数据、启动副作用
```

### 步骤 7：验证与自检

```
1. 执行 common-steps.md 步骤 D（验证 payload 完整性）
2. 执行 common-steps.md 步骤 E（静态分析自检）
3. 执行 review-checklist.md（复核清单）
4. 执行 common-steps.md 步骤 F（输出执行报告）
```

## 完成标准

- 所有新增文件符合命名规范
- 所有模块在装配器扫描范围内
- 注释比例 ≥ 配置值
- 单文件行数 ≤ 配置值
- payload 传递完整，无遗漏
- 静态分析自检通过
