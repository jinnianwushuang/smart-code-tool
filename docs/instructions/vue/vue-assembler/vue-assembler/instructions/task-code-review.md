# 代码检查指令

> 任务类型：代码检查
> 触发条件：用户需求包含「检查」「审查」「review」「合规」等关键词

## 前置依赖

- 门禁检查通过（gate-check.md）
- 信息完整性检查通过
- 任务类型已锁定为「代码检查」

## 执行步骤

### 步骤 1：确定检查范围

```
1. 明确检查目标（指定文件 / 目录 / 整个页面）
2. 读取目标文件
3. 如有不确定项 → 触发「存疑即问」
```

### 步骤 2：架构合规性检查

```
1. 检查模块是否按架构规范组织（state / module / component）
2. 检查函数命名是否符合规则（lifecycle_* / handle_* / cleanup_effect_*）
3. 检查 payload 传递是否正确
4. 检查是否存在绕过装配器的手动导入
```

### 步骤 3：命名规范检查

```
1. 文件名是否为 kebab-case
2. 变量名是否为 snake_case
3. 函数名前缀是否正确
4. 常量是否为大写
```

### 步骤 4：状态使用检查

```
1. 单例/多例状态是否正确使用
2. 计算属性是否存在循环依赖
3. init_singleton 是否正确实现
```

### 步骤 5：副作用清理检查

```
1. 所有副作用是否通过 cleanup_effect_* 注册
2. 是否存在框架外的手动监听器
3. 清理函数是否返回了数组
```

### 步骤 6：组件对接检查

```
1. 组件是否声明了对接文档
2. props/emit 是否正确声明
3. 是否存在组件内直接修改状态的情况
```

### 步骤 7：CSS 复用合规性检查

```
1. 是否优先使用了框架组件和全局 CSS 变量
2. 是否存在不通用的自定义 CSS
3. 全局 CSS 变量是否在 config.md 清单中
```

### 步骤 8：代码量检查

```
1. 单文件行数是否 ≤ 配置值（默认 400）
2. 单函数行数是否 ≤ 配置值（默认 50）
3. 注释比例是否 ≥ 配置值（默认 10%）
```

### 步骤 9：生成报告

```
1. 汇总所有检查结果
2. 分类：通过项 / 告警项 / 不通过项
3. 生成报告文件，保存到「报告存放目录」
4. 文件名规则：{任务类型}_{检查目标}_{YYYY-MM-DD-HH-mm-ss}.md
5. 更新报告总表 _index.md，追加本次检查记录
```

### 步骤 10：输出

```
1. 执行 common-steps.md 步骤 F（输出执行报告）
```

## 完成标准

- 所有检查维度已覆盖
- 报告已生成并保存
- _index.md 总表已更新
- 报告中包含具体的改进建议
