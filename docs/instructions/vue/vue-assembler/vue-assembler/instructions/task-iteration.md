# 需求迭代指令

> 任务类型：需求迭代
> 触发条件：用户需求包含「迭代」「修改」「调整」「增加功能」等关键词

## 前置依赖

- 门禁检查通过（gate-check.md）
- 信息完整性检查通过
- 任务类型已锁定为「需求迭代」

## 执行步骤

### 步骤 1：理解现有代码

```
1. 读取目标文件/模块，理解现有代码结构
2. 明确需要迭代的具体内容
3. 确定影响范围（哪些文件需要修改）
4. 如有不确定项 → 触发「存疑即问」
```

### 步骤 2：增量修改

```
1. 按影响范围逐个文件修改
2. 执行 common-steps.md 步骤 B（修改现有模块）
3. 如需新增模块执行 common-steps.md 步骤 A
4. 每次修改保持最小影响原则
```

### 步骤 3：回归验证

```
1. 确认修改不影响现有功能
2. 执行 common-steps.md 步骤 D（验证 payload 完整性）
3. 执行 common-steps.md 步骤 E（静态分析自检）
4. 检查修改后的文件行数未超过约束
```

### 步骤 4：报告

```
1. 执行 review-checklist.md（复核清单）
2. 执行 common-steps.md 步骤 F（输出执行报告）
```

## 完成标准

- 迭代内容已实现
- 现有功能未受影响
- 静态分析自检通过
- 注释已同步更新
