# 指令约束 — AI 执行边界

> 以下约束为硬性规则，AI 执行过程中不可违反。

## 1. 单次执行约束

- **一次只能执行一类任务类型**
- 禁止混合执行多种任务（如同时做新需求开发和代码检查）
- 若用户提交包含多种任务类型的请求，必须拆分为多次独立执行
- 每次执行前必须锁定唯一任务类型

## 2. 存疑即问约束

- 任务信息不全或存在疑义时，**必须暂停执行并向使用者提问确认**
- 提问时需**给出建议选项**（至少 2 个）或直接让使用者给出方案
- **禁止瞎猜、禁止脑补需求**
- 等待使用者回复后才能继续执行

## 3. 安全熔断约束

- 任务不在指令集有效范围内时，**必须停止执行**并明确告知使用者原因及需完善的点
- 执行过程中遇到无法解决的问题卡点时，**必须主动停止**并列出卡点清单及需要使用者提供的内容
- **禁止强行编造或跳过问题**

## 4. 验证边界约束

- 重构/修改代码完成后，**默认只走静态分析**（代码规范检查、架构合规性检查）
- **不主动启动项目运行验证**
- 仅当以下情况才执行运行验证：
  - config.md 中 `auto_run_verification` 配置为 `true`
  - 用户在任务命令中明确要求启动验证
- 完成静态分析后，**可建议使用者手动启动项目自检**

## 5. CSS 复用约束

- **禁止产生不通用 CSS**
- 写样式前**必须先查阅 config.md 中的项目可用资源清单**
- 遵循优先级链：框架组件 > 插件 > 全局 CSS/变量 > 自定义 scoped CSS
- 使用全局 CSS 变量前，确认该变量已在 config.md 的 `css_variables` 中列出

## 6. 不可修改的文件

以下文件为架构核心，AI 执行任务时**不可修改**：

- `assembler/assembler.js` — 装配器核心（除非任务明确要求修改装配器）
- `useContextAssembler` 的源码 — 属于公共模块
- `atoms_assembler` 的源码 — 属于公共模块

## 7. 不可跳过的步骤

以下步骤在任何任务中都**不可跳过**：

- 门禁检查（gate-check.md）
- 信息完整性检查
- 代码规范自检（code-standard.md）
- 复核清单（review-checklist.md）

## 8. 代码生成约束

- 生成的代码必须满足 config.md 中的代码生成约束配置
- 未配置则使用指令集默认值：单文件 ≤ 400 行、注释 ≥ 10%、单函数 ≤ 50 行
- 每次生成代码后必须自检是否满足这些约束
