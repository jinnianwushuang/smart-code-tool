# 修复指令

> 任务类型：修复
> 触发条件：用户需求包含「修复」「bug」「报错」「异常」等关键词

## 前置依赖

- 门禁检查通过（gate-check.md）
- 信息完整性检查通过
- 任务类型已锁定为「修复」

## 执行步骤

### 步骤 1：问题定位

```
1. 读取相关文件，理解报错上下文
2. 定位报错/异常的具体位置
3. 分析报错原因
4. 如有不确定项 → 触发「存疑即问」
```

### 步骤 2：根因分析

```
1. 确认是代码逻辑问题 / 架构使用不当 / 配置缺失 / 依赖问题
2. 确定修复方案（最小改动原则）
3. 评估修复是否会影响其他功能
```

### 步骤 3：修复

```
1. 执行 common-steps.md 步骤 B（修改现有模块）
2. 修复代码，遵循命名规范和注释规范
3. 添加修复说明注释
```

### 步骤 4：验证

```
1. 执行 common-steps.md 步骤 D（验证 payload 完整性）
2. 执行 common-steps.md 步骤 E（静态分析自检）
3. 确认修复不引入新问题
```

### 步骤 5：报告

```
1. 执行 review-checklist.md（复核清单）
2. 执行 common-steps.md 步骤 F（输出执行报告）
3. 报告中包含：问题原因、修复方案、影响范围
```

## 完成标准

- 问题已修复
- 修复方案符合架构规范
- 静态分析自检通过
- 未引入新问题
- 报告中说明了根因和修复方案

## 验证建议

修复完成后，建议使用者手动启动项目自检，确认问题已解决。
