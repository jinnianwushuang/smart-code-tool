# 重构指令

> 任务类型：重构
> 触发条件：用户需求包含「重构」「优化」「改造」「迁移」等关键词

## 前置依赖

- 门禁检查通过（gate-check.md）
- 信息完整性检查通过
- 任务类型已锁定为「重构」

## 执行步骤

### 步骤 1：现状分析

```
1. 读取目标文件/模块，理解现有代码结构和功能
2. 识别当前问题（复杂度过高 / 职责不清 / 不符合架构规范 / 等）
3. 列出需要保留的功能点
4. 如有不确定项 → 触发「存疑即问」
```

### 步骤 2：目标架构映射

```
1. 确定重构目标架构（参照 architecture/ 参照文件）
2. 设计重构后的文件结构和模块划分
3. 列出重构后需要创建/修改/删除的文件清单
4. 确认重构方案不丢失现有功能
```

### 步骤 3：逐步迁移

```
1. 按模块逐步迁移，每次迁移一个模块
2. 每迁移一个模块后执行 common-steps.md 步骤 B（修改现有模块）
3. 如需新建模块执行 common-steps.md 步骤 A（创建新的模块文件）
4. 保持每步可验证，不一次性大规模改动
```

### 步骤 4：验证等价性

```
1. 对比重构前后的功能点，确保无遗漏
2. 执行 common-steps.md 步骤 D（验证 payload 完整性）
3. 执行 common-steps.md 步骤 E（静态分析自检）
4. 检查装配器是否能正确发现所有新模块
```

### 步骤 5：清理与报告

```
1. 删除不再需要的旧文件/代码
2. 更新相关引用
3. 执行 review-checklist.md（复核清单）
4. 执行 common-steps.md 步骤 F（输出执行报告）
```

## 完成标准

- 重构后代码符合架构规范
- 所有功能点保留，无遗漏
- 静态分析自检通过
- 旧代码已清理，无冗余文件
- 注释比例 ≥ 配置值

## 验证建议

重构完成后，建议使用者手动启动项目自检，确认功能等价。
