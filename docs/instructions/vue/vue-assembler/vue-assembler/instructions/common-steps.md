# 通用基础步骤

> 各任务类型复用的公共步骤片段。每个任务指令文件在执行过程中引用本文件中的步骤。

## 步骤 A：创建新的模块文件

```
1. 确定模块类型（状态 / 事件管道 / 副作用 / 工具方法）
2. 确定文件放置位置（参照 architecture/directory-convention.md）
3. 创建文件，按命名规则命名（kebab-case）
4. 编写代码，遵循以下模板：
   - 事件处理函数：export const handle_xxx = (payload) => { ... }
   - 副作用清理：export const cleanup_effect_xxx = (payload) => { return [...] }
   - 状态声明：export const xxx = ref(默认值) + export const init_singleton = () => { ... }
5. 添加中文注释（比例 ≥ 10%）
6. 确认文件在 import.meta.glob 扫描范围内（无需手动注册）
```

## 步骤 B：修改现有模块

```
1. 读取目标模块文件，理解现有代码
2. 确定修改范围，不影响其他函数
3. 修改代码，遵循命名规范和注释规范
4. 确认修改后文件行数未超过约束上限
5. 确认修改不会破坏装配器的自动发现
```

## 步骤 C：创建新的组件文件

```
1. 确定组件类型（对话框 / 表格单元格 / 搜索区域 / 其他）
2. 确定组件放置位置（component/ 对应子目录下）
3. 创建 .vue 文件，使用 <script setup> 组合式 API
4. 声明 props 和 emit
5. 声明对接文档（父级提供什么状态、通道、函数）
6. 编写模板和逻辑
7. 如需注册到配置（如 dialog_wrapper_config），更新对应 config.js
```

## 步骤 D：验证 payload 完整性

```
1. 检查新函数是否从 payload 中解构了所有需要的状态和方法
2. 检查 payload 中是否包含所需的所有单例/多例状态
3. 检查事件管道函数是否可通过 ALL_EVENT_PIPELINE 访问
4. 如有缺失，检查是否需要更新 state/ 或 expose.js
```

## 步骤 E：静态分析自检

```
1. 命名规范检查：文件名 kebab-case、变量名 snake_case、函数前缀正确
2. 注释比例检查：注释行数 / 总行数 ≥ 配置值（默认 10%）
3. 文件行数检查：单文件 ≤ 配置值（默认 400 行）
4. 函数行数检查：单函数 ≤ 配置值（默认 50 行）
5. 架构合规性检查：模块职责单一、payload 传递正确、无循环依赖
6. CSS 复用检查：是否优先使用了框架组件和全局变量
```

## 步骤 F：输出执行报告

```
1. 列出本次任务创建/修改的所有文件
2. 列出每个文件的关键变更
3. 列出静态分析自检结果
4. 如有告警或建议，一并列出
5. 如配置了代码检查报告，保存到指定目录
```
