# 约束规则规范

> 指令集执行时的五大控制机制：门禁、规范、约束、熔断、边界

---

## 概述

每条指令在设计时必须内置这五类控制机制，确保 AI 行为可控、可预期、不越界。

| 机制 | 触发时机 | 核心目的 | 设计产出 |
|------|---------|---------|---------|
| 门禁 | 执行前 | 确保条件具备才执行 | 前置条件清单、环境检查项 |
| 规范 | 执行中（软性） | 保证输出质量和一致性 | 格式模板、命名规则、引用规则 |
| 约束 | 执行中（硬性） | 防止越界操作 | 作用域白名单、禁止操作清单 |
| 熔断 | 异常时 | 防止错误扩散 | 停止条件、卡点上报格式 |
| 边界 | 全程 | 明确能力范围 | 能做/不能做清单、确认触发条件 |

---

## 1. 指令门禁（Gate Check）

> 执行前的准入检查，不满足条件则拒绝执行

### 检查项

| 检查类型 | 说明 |
|---------|------|
| 前置条件校验 | 定义必要输入参数清单，检查上下文是否完整 |
| 环境检查 | 确认当前项目状态是否允许执行（分支、依赖等） |
| 权限检查 | 确认当前操作是否在指令集授权范围内 |
| 存疑即问 | 信息不完整或存在歧义时，必须主动提问确认，禁止自行猜测 |

### 示例

```markdown
## 门禁检查

执行本指令前，确认以下条件：

- [ ] 参数 module 已提供且指向有效目录
- [ ] 当前分支为开发分支（非 main/master）
- [ ] 依赖已安装（node_modules 存在）
- [ ] 已加载第 1 层基础上下文

任一条件不满足 → 停止执行，提示补充
```

---

## 2. 规范（Specification）

> 执行过程中应遵守的行为规范（软性，保证质量）

### 规范项

| 规范类型 | 说明 |
|---------|------|
| 单次执行约束 | 一条指令只承担一类任务，禁止混合多种任务类型 |
| 输出格式规范 | 每类指令的输出必须符合预定义的格式模板 |
| 命名规范 | 生成的文件、函数、变量必须遵循项目命名约定 |
| 引用规范 | 修改代码时必须引用对应的架构参照文件，确保一致性 |

---

## 3. 约束（Constraint）

> 执行过程中的硬性限制，不可违反

### 约束项

| 约束类型 | 说明 |
|---------|------|
| 作用域约束 | 每层指令只能操作其定义范围内的文件/目录 |
| 依赖约束 | 不得引入项目未声明的依赖，不得升级未经评审的依赖版本 |
| 架构约束 | 不得违反项目既定的架构分层规则（如跨层调用、循环依赖） |
| 安全约束 | 不得修改配置文件中的敏感信息（密钥、证书等） |

---

## 4. 熔断（Circuit Breaker）

> 异常情况的自动停止机制，防止错误扩散

### 熔断条件

| 熔断类型 | 触发条件 | 行为 |
|---------|---------|------|
| 范围熔断 | 任务不在指令集有效范围内 | 立即停止，说明原因及需完善的内容 |
| 卡点熔断 | 遇到无法解决的问题 | 主动停止，列出卡点清单 |
| 置信度熔断 | AI 对输出结果置信度低于阈值 | 标记为"需人工确认"而非强行输出 |
| 递归熔断 | 检测到循环依赖或无限递归风险 | 立即中断并报告 |

### 禁止行为

- 禁止强行编造
- 禁止跳过问题
- 禁止静默失败

---

## 5. 边界（Boundary）

> 明确指令集"能做什么"和"不能做什么"的界限

### 边界项

| 边界类型 | 说明 |
|---------|------|
| 验证边界 | 默认只做静态分析，不主动启动项目运行验证；仅当明确配置或要求时才执行 |
| 分析边界 | 明确区分"可自动修复"和"仅报告建议"的操作类型 |
| 认知边界 | AI 应明确声明哪些结论基于代码分析、哪些基于推测 |
| 操作边界 | 定义哪些操作需要人工确认后才能执行（如删除文件、修改公共配置） |

---

## 在指令文件中的声明方式

每条指令文件应包含控制机制声明：

```markdown
<!--
@instruction: 新功能开发
@mode: parameterized
@gate:
  - 参数 module 必须提供
  - 已加载基础上下文
@constraints:
  - 仅操作 module 指定目录下的文件
  - 不得修改 shared/ 目录
@circuit_breaker:
  - 遇到架构违规立即停止
  - 不确定时标记为"需确认"
@boundary:
  - 只做静态分析
  - 不自动删除文件
-->
```
