# 参数管道设计

> 不强制统一格式，按指令集实际需求设计；无参数的指令直接执行，零记忆负担

---

## 设计原则

1. 不是所有指令都需要参数
2. 固定明确执行流程的指令，无需参数，直接从入口文件选中执行
3. 不同指令集的参数设计可能不一样，不强制统一
4. 必须有参数的指令，才需要设计参数格式

---

## 两种执行模式

| 模式       | 适用场景                     | 调用方式                     | 示例                                                             |
| ---------- | ---------------------------- | ---------------------------- | ---------------------------------------------------------------- |
| 直接执行   | 流程固定、无需外部输入       | 从 `entry.md` 选中指令直接跑 | 基础提示词加载、健康度巡检、上线前检查                           |
| 参数化执行 | 需要指定作用域、类型、范围等 | 提供参数后执行               | 日常开发（指定模块）、代码检查（指定文件）、文档生成（指定类型） |

---

## 各层参数需求分析

| 层级               | 参数需求     | 说明                                             |
| ------------------ | ------------ | ------------------------------------------------ |
| 第 1 层 健康度巡检 | 可选参数     | 默认全量巡检，可指定模块范围                     |
| 第 2 层 基础提示词 | **无参数**   | 固定流程，直接加载全部上下文                     |
| 第 3 层 日常开发   | **必须参数** | 模块路径、组件名、任务类型等，每条子指令参数不同 |
| 第 4 层 代码检查   | 可选参数     | 默认全项目检查，可指定文件/目录范围              |
| 第 5 层 上线检查   | **无参数**   | 固定流程，按核心功能清单逐项检查                 |
| 第 6 层 文档生成   | **必须参数** | 文档类型、作用域、输出位置                       |

---

## 参数声明规范

每条指令在其文件顶部声明参数，格式统一：

```markdown
<!--
@instruction: 新功能开发
@mode: parameterized
@params:
  - name: module
    type: string
    required: true
    description: 目标模块路径
    example: project/code-tool-app/pages/excel-stats
  - name: component
    type: string
    required: false
    description: 目标组件名（不指定则操作整个模块）
-->
```

无参数指令同样声明，明确标注：

```markdown
<!--
@instruction: 基础提示词加载
@mode: fixed
@params: none
-->
```

---

## 参数传递方式

不同指令集可根据自身场景选择合适的方式，不强制统一：

| 方式         | 适用场景                   | 示例                                |
| ------------ | -------------------------- | ----------------------------------- |
| 行内参数     | 参数少（1-2 个），简单直接 | `执行 fix 指令，module=pages/login` |
| 参数块       | 参数多（3+ 个），结构清晰  | 在指令调用时附带 YAML 参数块        |
| 配置文件引用 | 参数可复用、需持久化       | 指令读取 `config.md` 中的预配置     |

---

## 参数校验规则

| 校验项   | 说明                                                    |
| -------- | ------------------------------------------------------- |
| 必填检查 | `required: true` 的参数未提供时，触发门禁拦截，提示补充 |
| 类型检查 | 参数值必须符合声明的 type（string / path / enum）       |
| 范围检查 | path 类型参数必须指向实际存在的目录/文件                |
| 存疑即问 | 参数值有歧义时，不猜测，主动询问确认                    |

---

## 设计决策

| 决策                              | 理由                                                       |
| --------------------------------- | ---------------------------------------------------------- |
| 不强制跨指令集统一参数格式        | 不同层、不同指令集的参数场景差异大，强制统一反而增加复杂度 |
| 参数声明放在指令文件顶部          | 声明即文档，AI 读取指令文件时自动获取参数定义              |
| 无参数指令明确标注 `@mode: fixed` | 入口文件可直接列出所有"一键执行"的指令，降低使用门槛       |
| 参数传递方式可选                  | 行内、参数块、配置文件三种方式按场景选择，实用为主         |
| 校验失败触发门禁                  | 与约束规则中的指令门禁机制联动，参数不齐不执行             |
