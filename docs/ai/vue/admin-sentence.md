# 企业级后台系统-基础提问语句

针对**企业级后台系统**，前端开发中 70% 的工作量集中在“表单、表格、权限、大数椐可视化”这几个场景。

以下是为您定制的高频业务场景提问模板：

## 1. “万能”高级搜索表格（Table + Search）

> **痛点：** 筛选条件多、分页逻辑重复、Loading 状态管理繁琐。

**Prompt 语句：**

> “请基于 **Vue 3 + [Element Plus/Ant Design Vue]** 封装一个标准的高级搜索列表页面。
> **场景描述：** 处理 **[业务名，如：订单管理]** 列表。
> **具体要求：**
>
> 1. **搜索栏：** 包含输入框、下拉单选、日期范围选择，支持‘展开/收起’功能。
> 2. **表格列：** 包含序号、[具体字段 1]、[具体字段 2]、状态标签（不同状态颜色不同）、操作列（编辑/删除）。
> 3. **逻辑要求：** 使用 **Composable (useTable)** 封装分页、自动请求接口、重置搜索条件等逻辑。
> 4. **响应式：** 适配不同屏幕宽度，表格高度需自适应以支持内部滚动。”

---

## 2. 动态多级权限/菜单管理

> **痛点：** 权限颗粒度控制、路由动态挂载、按钮级权限开关。

**Prompt 语句：**

> “我需要实现一套企业级的 **RBAC 权限控制方案**。
> **环境：** Vue 3 + Vue Router + Pinia。
> **任务：**
>
> 1. **路由动态挂载：** 如何在登录后根据后端返回的 `menus` 数组（树结构）动态添加路由？
> 2. **按钮权限：** 请编写一个自定义指令 `v-permission`，根据当前用户的 `permissions` 数组判断是否显示按钮。
> 3. **面包屑：** 如何配合路由守卫自动生成当前页面的面包屑路径？
>    **代码风格：** 请给出清晰的目录结构建议和核心逻辑实现。”

---

## 3. 复杂大表单与校验逻辑

> **痛点：** 嵌套结构深、字段级联联动、动态增减项。

**Prompt 语句：**

> “帮我设计一个 **[业务名，如：供应商入驻]** 的复杂表单。
> **结构要求：**
>
> 1. **分组显示：** 包含基本信息、资质信息（图片上传）、联系人（动态增减行）。
> 2. **表单联动：** 当‘类型’选择‘企业’时，显示‘营业执照’字段；选择‘个人’时隐藏。
> 3. **校验：** 使用 `rules` 实现严格校验（包含手机号正则、必填项、以及异步校验名称是否重复）。
> 4. **性能：** 如果表单项超过 50 个，请提供避免输入卡顿的优化建议。”

---

## 4. 数据大盘/可视化报表

> **痛点：** Echarts 容器初始化失败、窗口缩放不自适应、数据更新图表不刷新。

**Prompt 语句：**

> “我要在 Vue 3 页面中集成 **Echarts** 实现数据大盘。
> **需求：**
>
> 1. **封装：** 创建一个通用的 `BaseChart` 组件，支持通过 `props` 传入 `options`。
> 2. **生命周期：** 妥善处理 `onMounted` 初始化和 `onBeforeUnmount` 销毁，防止内存泄漏。
> 3. **自动调整：** 监听窗口 `resize` 事件，并使用 `markRaw` 避免 Echarts 实例被响应式代理导致性能问题。
> 4. **交互：** 点击柱状图时，需要触发 Vue 组件定义的 `emit` 事件。”

---

## 💡 针对后台系统的 3 个“专业级”微调指令：

- **关于 API 调用：** “请假设我已经封装好了 `request.ts`（基于 axios），请直接在代码中使用 `const res = await getList(params)` 的形式。”
- **关于样式：** “请尽可能使用组件库的 **内建变量或实用类**（如 Tailwind），避免写过多的原生 CSS。”
- **关于 TS 严谨性：** “请为接口返回的数据结构定义严格的 `interface`，不要使用 `any`。”
