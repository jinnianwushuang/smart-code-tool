# 指令集设计理念

> 本章节聚焦指令集的**设计方法论**——如何设计一套好的 AI 指令集体系。
> 具体框架指令集的实现与迭代已迁移至 smart-dev-kit 仓库。

---

## 什么是指令集

指令集是一套**面向 AI 助手**的结构化指令文件。将指令集拷贝到目标项目中，修改配置后，AI 助手即可按照指令快速完成符合特定架构规范的开发任务。

核心理念：**复制 → 改配置 → 傻瓜式快速使用**。

---

## 指令集体系设计

指令集体系定义了「怎么设计指令集」，是整个指令集系统的方法论层：

- **六层指令模型**：从基础提示词到文档生成的分层架构
- **设计要求**：术语映射、门禁、规范、约束、熔断、边界
- **注解驱动文档**：AUTO_DOC 注解跨语言自动生成文档
- **执行模型**：单指令执行、内嵌步骤、编排执行三种模式

→ [指令集体系设计总览](./instruction-architecture/)

## 指令集内部结构

每个指令集目录内部分为两个区域：

| 区域             | 受众      | 说明                                                    |
| ---------------- | --------- | ------------------------------------------------------- |
| `docs/`          | 人类      | 设计架构文档、配置指南、执行流程说明（VitePress 渲染）  |
| `<指令集名称>/`  | AI        | AI 指令文件、配置模板、架构参照（拷贝走的部分）         |
| `code-template/` | 开发者    | 核心代码模板（仅代码模板类指令集，如 vue-arch-starter） |
| `VERSION.md`     | 人类 + AI | 版本号与变更记录                                        |

## 设计原则

| 机制         | 触发时机       | 核心目的                 |
| ------------ | -------------- | ------------------------ |
| 专业术语映射 | 全程           | 统一 AI 与团队的概念理解 |
| 指令门禁     | 执行前         | 确保条件具备才执行       |
| 规范         | 执行中（软性） | 保证输出质量和一致性     |
| 约束         | 执行中（硬性） | 防止越界操作             |
| 熔断         | 异常时         | 防止错误扩散             |
| 边界         | 全程           | 明确能力范围             |

→ [约束规则规范](./instruction-architecture/standards/constraint-rules)
