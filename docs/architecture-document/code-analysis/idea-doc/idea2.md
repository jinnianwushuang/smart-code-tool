## 🛡️ 前端代码质量分析平台技术选型白皮书 (V3.0 工业级架构)

## 一、 核心设计理念

本系统采用 **“边缘计算，云端汇总”** 的思想：

- **本地端（重量客户端）**：负责敏感源码解析、高负载插件调度与二次加工。源码不出本地，确保企业代码安全。
- **服务端（轻量管控端）**：负责跨项目数据聚合、质量成长曲线分析、团队排名与报告分发。

## 三、 详细技术选型

## 1. 本地分析引擎 (The Engine)

- **核心语言**：**Rust**。利用其无 GC、高并发的特性，处理万级文件的深度解析。
- **插件机制**：基于 **Trait 模式** 封装。每个分析功能（如：代码冗余分析）为一个独立模块，由中控按需装配。
- **数据中转**：**DuckDB**。针对插件产生的大量中间数据（如数百万个 AST 节点信息），利用列式存储实现秒级的二次加工分析。
- **通信桥梁**：**NAPI-RS**。将 Rust 编译为 `.node` 原生扩展，供 Electron 主进程直接调用。

## 2. 云端管理中心 (The Hub)

- **服务端框架**：**NestJS**。利用其强大的依赖注入和模块化架构，支撑多项目组、多维度的权限管理。
- **数据上报**：采用 **Protobuf** 协议。客户端分析完成后，将高度压缩的指标数据上报至 NestJS。
- **质量大盘**：使用 **Vue 3 + ECharts**。展示团队代码质量的“成长曲线”，如：_“A 项目组本季度认知复杂度下降 15%”_。
- **自动化报告**：**Puppeteer**。在服务端定时渲染分析看板，自动生成 PDF 周报并推送到飞书/邮件。

---

## 四、 业务执行流 (Workflow)

1. **组装与触发**：用户在 **Quasar** 界面勾选“内置脚本集合”（如：Vue 解析 + 复杂度 + 依赖检查）。
2. **并发扫描**：**Rust 中控** 启动多线程，驱动各插件对本地源码进行流式解析。
3. **结果入库**：插件产出的中间结果实时写入本地 **DuckDB**。
4. **二次加工**：Rust 调用 SQL 算子对 DuckDB 中的原始指标进行加权计算，生成该项目的“质量画像”。
5. **轻量上报**：客户端剔除源码细节，仅将评估后的“指标数据”上报至 **NestJS** 服务端。
6. **成长看板**：服务端持久化数据，并在 Web 端更新该项目的成长曲线。

---

## 五、 方案优势

- **性能天花板**：Rust + DuckDB 组合确保了二次加工阶段即便面对海量指标也能瞬间完成。
- **源码安全**：重量客户端在本地完成所有分析，服务端仅存储“分值”和“趋势”，符合企业级合规要求。
- **高度灵活性**：NestJS 的模块化配合 Rust 的插件化，使得新增分析维度或管理功能互不干扰。
- **数字化度量**：通过长期记录成长曲线，让“代码质量优化”这一抽象工作变得可量化、可见。
