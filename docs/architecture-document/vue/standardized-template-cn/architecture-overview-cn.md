# 后端页面模板 - 架构概述

## 简介

后端页面模板是一个复杂的、可插拔的Vue.js后端页面架构，强调模块化、可组合性和清晰的关注点分离。它旨在标准化后端页面开发，同时保持高度的可扩展性。

## 核心架构原则

### 1. **可插拔模块系统**
每个组件（状态、生命周期、效果、事件、API请求）都是独立可加载和可组合的。模块通过Vite的`import.meta.glob()`自动发现，并在运行时组装。

### 2. **关注点分离**
该模板分离了：
- **状态管理**（单例、多例、计算属性）
- **生命周期钩子**（Vue 3生命周期事件）
- **事件处理**（发射、事件管道、用户交互）
- **副作用**（DOM、观察器、监听器、定时器、事件发射器）
- **API通信**（数据获取和转换）
- **组件组合**（具有可重用逻辑的UI组件）

### 3. **装配器模式**
架构的核心是**装配器模式**，它：
- 扫描并自动发现模块
- 将它们组合成内聚的单元
- 通过`useContextAssembler`可组合函数提供注入
- 消除手动模块导入和注册

## 目录结构

```
backend-page-template/
├── index.vue                 # 主页面组件
├── assembler/                # 装配器配置
│   └── assembler.js          # 主装配器设置
├── state/                    # 状态管理
│   ├── config.js             # 配置选项
│   ├── singleton.js          # 单例状态模块
│   ├── multiton.js           # 每实例状态模块
│   ├── computed.js           # 计算属性
│   └── singleton/            # 单例实现
│       ├── table.js          # 表格相关状态
│       ├── dialog.js         # 对话框相关状态
│       └── other.js          # 其他共享状态
├── module/                   # 业务逻辑模块
│   ├── lifecycle/            # Vue生命周期钩子
│   ├── emit/                 # Vue发射函数
│   ├── exposed-method/       # 公共API方法
│   ├── event-pipeline/       # 事件处理系统
│   ├── effect/               # 副作用清理
│   └── other-method/         # 实用方法
├── component/                # UI组件
│   ├── dialog-wrapper/       # 对话框包装器组件
│   ├── table-main-area/      # 表格主区域组件
│   └── top-search-area/      # 顶部搜索区域组件
├── api-request/              # API通信
│   └── module/               # API处理器
├── css/                      # 样式
└── docs/                     # 文档（生成的）
```

## 关键技术栈

- **Vue 3** - 具有组合API的UI框架
- **Vite** - 具有动态模块加载的构建工具
- **响应式系统** - Vue 3的`ref()`、`computed()`、`watch()`
- **Mitt** - 跨组件通信的自定义事件发射器
- **自动模块发现** - Vite的`import.meta.glob()`

## 执行流程

### 初始化阶段
1. 用户打开页面 → `index.vue`加载
2. `useContextAssembler()`初始化
3. 装配器扫描`/module/**`和`/state/*.js`目录
4. 模块被验证和组合
5. 单例状态初始化

### 运行时阶段
1. 组件使用装配器的状态渲染
2. 用户交互触发发射函数
3. 发射函数触发事件管道
4. 事件管道更新状态或触发API调用
5. API调用修改全局状态
6. Vue响应式传播变化到UI

### 清理阶段
1. 组件卸载
2. 效果清理处理器执行（监听器、观察器、定时器）
3. 单例状态为下次初始化保留
4. 资源释放

## 此架构的优势

| 特性 | 优势 |
|------|------|
| **模块化设计** | 易于理解、测试和维护单个模块 |
| **自动发现** | 无需手动注册 - 模块自动发现 |
| **可插拔** | 添加/删除模块而不改变核心代码 |
| **类型安全** | 清晰的模块接口和有效载荷结构 |
| **可扩展** | 成长中的项目组织一致 |
| **可重用** | 组件和逻辑可在页面间共享 |
| **可测试** | 具有依赖注入的纯函数 |
| **可配置** | 状态中的集中配置 |

2. **作为参考** - 研究模式用于自己的页面
