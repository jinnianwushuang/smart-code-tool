# 顶级大前端架构师日常自检复盘清单

在超一线科技公司，架构师的核心价值在于通过工程手段将“混沌”变为“有序”。本清单旨在提供一个多维度的自检框架，帮助架构师审视系统现状并预判潜在风险。

## 1. 每日必看：运行监控与稳定性 (Ops & Stability)

- [ ] **稳定性看板**：Sentry/OpenTelemetry 上的 JS Error 率是否突增？Top 5 错误是否已有解决方案？
- [ ] **核心性能指标**：昨日全站的 Core Web Vitals (LCP, CLS, INP) 采样数据是否在达标红线（如 75%）以上？
- [ ] **构建流水线**：CI/CD 成功率如何？是否存在因 pnpm 依赖冲突或缓存失效导致的构建耗时抖动？
- [ ] **技术债务响应**：今日是否有未闭环的紧急线上修复（Hotfix）？其对应的长期优化任务是否已排期？

## 2. 每周复盘：工程提效与治理 (Engineering Efficiency)

- [ ] **研发效能审计**：
    - 本周团队本地冷启动平均时长是否控制在 20s 以内 (Rspack/Vite 表现)？
    - 远程缓存 (Remote Cache) 的命中率是否处于高位？
- [ ] **组件库治理**：
    - 本周是否有新的“临时组件”产生？是否可以抽象到 shadcn/ui 或内部设计系统中？
    - 关键 API 的变更是否同步更新了 Storybook 文档？
- [ ] **依赖红线扫描**：本周 Snyk/SonarQube 扫描出的高危漏洞是否已全量修复？是否存在非法 License 的包混入？
- [ ] **代码审计 (High-Level CR)**：是否抽检了核心模块的代码？是否存在违背单一职责原则或滥用全局状态的情况？

## 3. 每月深度：架构演进与技术决策 (Architecture & Strategy)

- [ ] **架构决策记录 (ADR)**：本月的重大技术变更（如新引入的中间件或协议）是否已记录 ADR？Why 是否写得足够清晰？
- [ ] **RFC 评审进度**：正在推进的技术改造（如 Monorepo 目录重构）是否收到了各方的反馈？技术共识是否达成？
- [ ] **技术债量化**：当前遗留的旧版框架、过期补丁、无用代码片段的占比是否在下降？
- [ ] **ROI 评估**：上个月投入大量精力的技术基建（如全栈类型安全 tRPC 落地），是否真正降低了业务方的联调成本？

## 4. 团队成长与影响力 (Team & Leadership)

- [ ] **技术决策透明度**：本月的架构演进计划是否已向全员同步？初级开发者是否理解架构变动的初衷？
- [ ] **导师工作复盘**：被指导的高级开发者在架构设计思维（而非单纯代码量）上是否有实质性突破？
- [ ] **外部洞察**：本月是否调研了 2-3 个前沿开源项目（如 Bun/Farm/StyleX）？其中有哪些设计思路可以借鉴到现有系统？

## 5. AI 化程度自测 (AI-Native Index)

- [ ] **研发范式演进**：团队目前使用 Cursor/Copilot 的代码生成占比是否在提升？
- [ ] **自动化测试覆盖**：新增的测试用例中，由 AI 辅助生成的比例是多少？
- [ ] **智能化基建**：我们是否已开始利用 LLM 处理日志分析、文档自动生成或代码扫描？

## 6. 终极灵魂拷问 (The Architect's Core)

> **“如果明天业务规模扩大 10 倍，或者团队人数增加 10 倍，我现在的架构会崩塌吗？”**
