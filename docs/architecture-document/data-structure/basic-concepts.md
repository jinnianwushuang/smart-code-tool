# 数据结构基础概念

## 什么是数据结构?

数据结构是计算机存储、组织数据的方式,它决定了数据在内存中的布局和访问方式。选择合适的数据结构可以显著提升程序的性能和可维护性。

### 核心要素

1. **逻辑结构**: 数据元素之间的逻辑关系
   - 线性结构: 一对一关系(数组、链表)
   - 树形结构: 一对多关系(二叉树、堆)
   - 图状结构: 多对多关系(有向图、无向图)
   - 集合结构: 元素间无特定关系

2. **物理结构**: 数据在内存中的实际存储方式
   - 顺序存储: 连续内存空间(数组)
   - 链式存储: 非连续内存,通过指针连接(链表)
   - 索引存储: 建立索引表加速查找
   - 散列存储: 通过哈希函数直接定位

3. **数据运算**: 对数据执行的操作
   - 插入、删除、查找、排序、遍历

## 为什么需要数据结构?

### 性能优化

不同的数据结构在不同操作上有不同的时间复杂度:

```javascript
// 数组查找: O(n)
const arr = [1, 2, 3, 4, 5]
arr.indexOf(3) // 需要遍历

// 哈希表查找: O(1)
const map = new Map([
  [1, 'a'],
  [2, 'b'],
  [3, 'c'],
])
map.get(3) // 直接定位
```

### 代码可读性

使用合适的数据结构可以让代码意图更清晰:

```javascript
// 使用 Set 表示唯一值集合
const uniqueIds = new Set([1, 2, 3, 2, 1])
uniqueIds.add(4) // 自动去重

// 使用 Map 表示键值对映射
const userRoles = new Map([
  ['admin', ['read', 'write', 'delete']],
  ['user', ['read']],
])
```

### 解决特定问题

某些问题天然适合特定的数据结构:

- **浏览器历史记录**: 栈 (Stack)
- **任务调度**: 队列 (Queue) 或优先队列
- **文件系统**: 树 (Tree)
- **社交网络**: 图 (Graph)

## 数据结构的选择原则

### 1. 根据操作频率选择

| 操作类型      | 推荐数据结构           |
| ------------- | ---------------------- |
| 频繁查找      | 哈希表、平衡二叉搜索树 |
| 频繁插入/删除 | 链表、跳表             |
| 频繁排序      | 数组 + 堆              |
| 范围查询      | B树、B+树              |

### 2. 根据数据规模选择

- **小规模数据**: 简单数组即可,避免过度设计
- **中等规模**: 考虑哈希表、二叉树
- **大规模数据**: 考虑 B树、布隆过滤器等外部存储友好结构

### 3. 根据内存限制选择

- **内存充足**: 可以使用冗余结构加速查询(如索引)
- **内存受限**: 选择紧凑结构,或使用外部存储

## 常见数据结构分类

### 线性结构

- **数组 (Array)**: 连续内存,随机访问快
- **链表 (Linked List)**: 动态大小,插入删除快
- **栈 (Stack)**: LIFO (后进先出)
- **队列 (Queue)**: FIFO (先进先出)

### 树形结构

- **二叉树 (Binary Tree)**: 每个节点最多两个子节点
- **二叉搜索树 (BST)**: 左 < 根 < 右
- **平衡树 (AVL/红黑树)**: 自平衡,保证操作效率
- **堆 (Heap)**: 完全二叉树,用于优先队列
- **B树/B+树**: 多路搜索树,用于数据库索引

### 图结构

- **有向图/无向图**
- **加权图/无权图**
- **稠密图/稀疏图**

### 哈希结构

- **哈希表 (Hash Table)**: 键值对映射
- **集合 (Set)**: 唯一元素集合
- **布隆过滤器 (Bloom Filter)**: 概率性集合成员判断

## 时间复杂度对比

| 数据结构   | 查找     | 插入     | 删除     | 空间复杂度 |
| ---------- | -------- | -------- | -------- | ---------- |
| 数组       | O(n)     | O(n)     | O(n)     | O(n)       |
| 链表       | O(n)     | O(1)     | O(1)     | O(n)       |
| 哈希表     | O(1)     | O(1)     | O(1)     | O(n)       |
| 二叉搜索树 | O(log n) | O(log n) | O(log n) | O(n)       |
| 平衡树     | O(log n) | O(log n) | O(log n) | O(n)       |
| 堆         | O(n)     | O(log n) | O(log n) | O(n)       |

> **注意**: 以上为平均情况,最坏情况可能不同(如 BST 退化为链表时为 O(n))

## 实践建议

1. **不要过早优化**: 先用简单结构,遇到性能瓶颈再优化
2. **理解 trade-off**: 没有完美的数据结构,只有适合场景的选择
3. **善用标准库**: 大多数语言都提供了成熟的数据结构实现
4. **考虑缓存局部性**: 数组比链表对 CPU 缓存更友好
5. **测试边界情况**: 空结构、单元素、大量重复等
