# 团队建设 [TL]

> 团队建设是 TL 最重要的职责之一。2026 年，前端团队的招聘面试设计、工程师成长体系、1on1 方法论是管理能力的核心体现。

## 核心概念（What）

### 团队建设四要素

```
├── 招聘：找到对的人
├── 成长：让团队变强
├── 文化：建立信任和透明
└── 留存：让优秀的人留下来
```

---

## 底层原理（Why）

### 1. 面试设计

```
面试流程设计：
├── 简历筛选（15 分钟）
│   └── 关注：项目深度 > 技术广度
├── 电话面试（30 分钟）
│   └── 基础知识 + 项目经验
├── 技术面试（60 分钟）
│   └── 编码能力 + 系统设计 + 问题解决
├── 架构面试（60 分钟）
│   └── 架构设计 + 技术决策 + trade-off
└── 文化面试（30 分钟）
    └── 价值观 + 协作 + 成长心态

面试题目设计原则：
├── 开放性 > 封闭性（没有唯一答案）
├── 深度 > 广度（追问到候选人的边界）
├── 实战 > 背诵（场景题 > 概念题）
└── 过程 > 结果（思考方式 > 最终答案）
```

```
面试评估维度：
├── 技术深度：对核心技术的理解深度
├── 系统设计：复杂系统的设计能力
├── 问题解决：分析问题和解决问题的能力
├── 沟通表达：清晰表达复杂想法
├── 学习能力：学习新技术的速度和深度
├── 协作能力：团队合作和影响力
└── 文化匹配：价值观和做事方式
```

### 2. 工程师成长体系

```
成长体系设计：
├── 技术等级：P5 → P6 → P7 → P8 → P9
├── 能力模型：每个等级明确的能力要求
├── 发展计划：个人 IDP（Individual Development Plan）
├── 导师制度：高 P 带低 P
└── 技术分享：周会分享、技术博客

能力模型示例（P6 → P7）：
├── P6：独立完成复杂功能，解决技术问题
├── P7：设计模块架构，指导他人，跨团队协作
└── 差距：架构能力 + 影响力 + 主动性
```

### 3. 1on1 方法论

```
1on1 最佳实践：
├── 频率：每周或双周（30-60 分钟）
├── 议程：由被 1on1 的人主导
├── 重点：成长 > 汇报，感受 > 任务

1on1 话题框架：
├── 当前状态：工作进展、遇到的困难
├── 成长发展：学习目标、职业规划
├── 团队协作：合作关系、沟通问题
├── 反馈建议：对团队/TL 的建议
└── 个人感受：压力、动力、满意度

避免的陷阱：
├── 变成任务同步会（应该关注人而非事）
├── TL 一直说（应该多听少说）
├── 没有后续跟进（应该记录 action items）
└── 只在有问题时才 1on1（应该定期持续）
```

### 4. 团队文化建设

```
高效团队特征：
├── 心理安全：可以安全地犯错和提问
├── 透明沟通：信息自由流动
├── 技术卓越：追求高质量，但不完美主义
├── 持续学习：鼓励学习和分享
└── 结果导向：关注产出而非工时

文化建设活动：
├── 技术分享会（每周）
├── 代码评审文化（建设性反馈）
├── 黑客马拉松（季度）
├── 回顾会议（Sprint 回顾）
└── 非团队活动（聚餐、运动）
```

## 高频面试题

### Q1: 如何设计前端面试流程？

**参考答案要点**：

- 多轮面试（基础 → 技术 → 架构 → 文化）
- 面试题目开放性强（场景题 > 概念题）
- 评估维度明确（技术深度、系统设计、沟通、协作）
- 面试官培训（统一标准，避免偏见）

### Q2: 如何帮助团队成员成长？

**参考答案要点**：

- 制定个人发展计划（IDP）
- 分配有挑战性的任务（舒适区之外）
- 导师制度（高 P 带低 P）
- 定期 1on1（关注成长而非任务）
- 技术分享和博客输出

### Q3: 如何处理团队中的低绩效成员？

**参考答案要点**：

- 先诊断原因（能力不足？动力不足？方向不对？）
- 明确期望和改进计划（PIP）
- 提供支持和资源（培训、导师）
- 设定时间线（30/60/90 天）
- 如果无法改善，坦诚沟通转岗或离开
